一句话概述

微软 CEO 萨蒂亚·纳德拉在雷德蒙德接受格尔盖伊·奥罗斯访谈：当代码生成变便宜，难的是验证。两人从微软的开源转向、在开放中打造 VS Code，谈到 GitHub Copilot 一度领先、Cursor 的 Agent 模式，以及 2025 年 Claude Code 让 CLI 成为新形态、IDE 在约六个月内明显淡出。纳德拉把决策引擎比作智能时代的存储过程，解释“软件工厂”意味着规格、意图、验证与生产轨迹回流；并讨论自愿退出方案、初级招聘放缓不必过早当成长期趋势，以及企业必须自握编排、上下文与学习回路，否则谈不上主权。节目说明：本集录于微软 Outlook 全日故障开始前几小时，节目中没有谈论这次故障，主持人预告将在通讯中做后续复盘。

核心要点

  • 纳德拉承认：Copilot 在 ChatGPT 3.5 之前就以补全取胜，Cursor 后来在 Agent 模式上领先；真正打中微软的是 Anthropic 的模型让 CLI 成为一种形态，代码从输入变成产出，约六个月里 IDE 明显淡出。模型非线性跃迁时，产品形态必须跟着改，不能迷恋已经做出的东西。
  • 决策引擎被他称作智能时代的“存储过程”：像 Excel 宏一样把智能嵌进软件，有分布、可重复调用、省 token；Xbox 处理社区反馈时不必每次都让大模型生成代码。软件工程并未消失，而是换了原语。
  • “软件工厂”：代码变成产出之后，关键变成规格与意图、对齐，以及把失败回流成测试的验证，再加上把生产日志拿回来验证修复的可验证闭环（他称之为自己版本的 RSI）。Azure 网络团队管理全球约 500 个光纤运营商，用智能体系统把原先靠邮件和临时流程的运维接到代码仓库。GitHub 一侧，一名开发者维护整套运行时并（他记得）向 Rust 迁移；另一支大约 9 到 12 人的团队就撑起一座工厂。
  • 棕地才是现实：Windows 从崩溃轨迹到修复、用模型发现的 CVE 都要新流水线，但构建系统和 CI/CD 仍是最难部分；GitHub 因编码智能体流量暴涨，要改 Git 协议和存储。这和当年掺入 React 不同——运行时、框架、IDE 与抽象层级都可能被新模型再次改写。
  • 自愿退出方案是给约 20 万人更多能动性，把人配置到新机会上，而不是他能保证每个团队都以他想要的节奏转型；驻场工程师（FDE）是微软增长最快的岗位之一。初级招聘放缓，他建议先看内部工厂是否建好、再判断能不能高杠杆地吸收新人和 token，现在下长期结论还太早。
  • 他不相信会有一个前沿模型装下世界全部知识；并引用哈耶克：知识是分散的，每家公司都将同时拥有人力资本和 token 资本。编排、上下文/记忆、动作空间必须与模型解耦，酸检测试是能否在私有评估上换模型还能爬坡。缩放带来能力却不带来对齐，必须把权威与智能分开，把智能体当内部风险来治理；思维链要用人能审计的语言而不是神经语（neuralese）。本地模型与 Copilot Fusion 路由把端侧变成“不计量的智能”。他的建议是：少追标题，回到动手与“上学模式”。

  1. 1开场：开源转向，以及在开放中打造 VS Code查看原文 →

    纳德拉在冷开场里点出主题：代码生成变便宜之后，难的是验证；“代码即产出”有自己的操作顺序，不是随机生成代码。主持人格尔盖伊·奥罗斯介绍嘉宾：纳德拉是少数从软件工程师做起的大型科技公司 CEO，本集将谈软件工厂、开放与本地模型、“不计量的智能”、开发者焦虑、自愿退出方案，以及初级招聘放缓为何可能只是暂时现象。进入正题后，格尔盖伊说自己曾是微软人，2014 年纳德拉出任 CEO 时他在伦敦，这是他第一次来雷德蒙德总部。他记得当时微软仍偏封闭源，而纳德拉上任后转向开源：发布 Visual Studio Code、收购 GitHub、全面拥抱 Git（此前用的是 TFS），并把 TypeScript 开源，连他自己当时都感到意外。纳德拉回应：叙事一旦形成就很难改，但即便在他出任 CEO 之前，微软对 Linux 的提交已经相当可观。他们要让内外都看清对开源的承诺：把 SQL Server 等负载带到 Linux、贡献 Linux、开源 TypeScript，再加上作为 GitHub 的管家，必须靠对社区做对的事来赢得信任。他认为若认真核算开源使用与贡献，微软会处在最靠前的位置；相反，不少从开源获益最多的公司几乎没怎么贡献——世界常常被叙事而不是事实驱动。格尔盖伊把最大影响归到 VS Code：它不仅开源，而且免费；他以前用的 Visual Studio 2003 已经非常出色，但微软把免费、开源的 Visual Studio 带给更广泛的开发者，五年、十年后几乎无处不在。这是不是有意为之？纳德拉说完全是有意的，埃里克·伽马（Erich Gamma）等人当时就在推动，而且那是他第一次真正接触“在开放中构建”：每天对着社区反馈做产品，而不是听命于副总裁。产品经理阿曼达·西尔弗（Amanda Silver）所在团队的工作方式，带来的是超越开源许可本身的文化转变。他觉得这些教训本该学得更深、推得更广。

  2. 2Copilot 领先一年，随后被 Cursor 与 Claude Code 改写形态查看原文 →

    格尔盖伊回顾：在 ChatGPT 3.5 之前，大约在 GPT-3 / Codex 那一代，GitHub Copilot 的补全就已经“像魔法”，此后至少一年几乎没有真正对手，直到 2023 年 Cursor 出现。Cursor 基于 VS Code 的熟悉界面，与 Copilot 并跑竞争。然后 2025 年 Claude Code 横空出世，大约六个月里，连大厂的人仿佛都忘了 IDE。微软以开发者工具为基因，为什么没有立刻接住这次突变？纳德拉承认值得拆开讲。Copilot 起步于 GPT-4 之前，补全效果让他本人对扩展定律的信心得到根本性印证；此前他们对 IntelliSense 做了很久，也有很多人怀疑这条路走不通。用模型做产品的关键是：模型非线性跃迁时，形态必须马上改，不能迷恋已经做出的东西——AI 优先的产品构建在这一点上不留情面。当可以给模型分配小任务、而不只是补全时，Cursor 把 fork 来的 IDE 在 Agent 模式上做出了成绩，微软随后在 OpenAI 模型之上补上了 Agent 模式。真正打中他们的，是 Anthropic 的模型让 CLI 成为一种形态，代码从输入变成产出。大约六个月里，IDE 明显淡出。他并不认为这是永久转移：随着决策引擎出现，IDE 可能以“把智能函数嵌进软件、更省 token”的方式重生，关键是同时拥有多种形态去匹配模型能力。

  3. 3决策引擎：智能时代的存储过程查看原文 →

    格尔盖伊问：两人都刚在不同场合和迪奥戈·阿尔梅达（Diogo Almeida）交谈过，纳德拉对决策模型、以及对大语言模型在编程这类可编程任务上的限度，看法有没有变？纳德拉先承认大语言模型很出色，主持人打断说既是工程师，就直接切到它们不好的地方。纳德拉说，他喜欢决策引擎，是因为它像一种新原语。迪奥戈以及微软自己的决策引擎都在谈这件事。他的类比是 Excel 宏：宏曾让电子表格大变，现在也可以把智能作为原语嵌进代码。它有分布、可以调用、不必反复生成，因而省 token。他举了 Xbox 处理社区反馈的系统：反馈进来后要做一组决策，这时不必让大模型每次生成代码，把决策原语嵌进去更好。软件工程在这里仍然非常活着，只是在变。他欣赏把决策引擎做得“像数据库一样无聊”的目标——关系数据库曾是他在开发者工具链里（除了编译器、lex 和 yacc）最喜欢的产品，因为它让存储和查询变得可靠，从而让各类应用成为可能。决策引擎在智能时代可能扮演同样角色。格尔盖伊补充：软件公司的本质常被说成业务逻辑，但再往下看，逻辑往往就在数据库里，过去很多业务逻辑写在存储过程、存储事务中。纳德拉接过这个类比：这就是智能时代的存储过程。格尔盖伊希望能找到这类仍缺失的可靠原语：大语言模型能写代码，也能做不可靠的事，但还缺能托住系统的原语。

  4. 4代码变成产出之后，难的是验证查看原文 →

    纳德拉转到软件工厂：看 Copilot Cowork 或今天 GitHub Copilot 运行时的构建方式（已有人写过博客）就会发现，代码生成变便宜之后，难的是验证。他甚至想加入马克·拉西诺维奇（Mark Russinovich）、斯科特·汉塞尔曼（Scott Hanselman）他们做的 Perceptorship（导师见习）项目——据说还和卡内基梅隆大学有合作——因为自己还没在“代码主要是产出”的团队里干过。这种模式有操作顺序：不是人人乱生成代码，而是每次失败都要回流成测试用例，真正把验证做扎实。复杂项目里正在形成新的口口相传的知识；那次向 Rust 的迁移也曾不得不回退，说明既有巨大优势，也有严重代价。所以像决策引擎这样的额外原语是有价值的。他说，如果可以选下一份工作，梦想就是回到这样的小团队里亲手做。以前人们来微软实习，会去看戴夫·卡特勒（Dave Cutler）的代码、看 malloc 的实现；现在必须找到那种学习曲线的新形态，也让早期职业者能加入这些团队往上走。格尔盖伊因此明白，为什么那么多 CTO、工程副总裁愿意降级到小团队，去学用新工具构建。纳德拉认为，大变革时期更要亲手做、贴近客户、在开放中构建。

  5. 5软件工厂：规格、验证，以及生产轨迹回流查看原文 →

    对“软件工厂”这个有点含混的词，纳德拉说自己也还在摸索，是在对今天软件团队的工作做模式匹配。他建议观众去看巴斯（Bass）写的博客，以及 Copilot Cowork 团队和 GitHub Copilot 团队各一篇。GitHub 那边的案例是：一名开发者维护整套运行时，并（他记得，拿不准是不是从 Python）迁到了 Rust——主持人笑说“总是迁到 Rust”。这是单人生产力的漂亮案例。另一边，大约 9 到 12 名工程师就撑起一座软件工厂，团队规模小得惊人。根本转变是：代码从输入变成产出，于是规格和意图——设计文档、对齐——变得更关键。一位早期职业者告诉他，现在进入代码库反而更容易，因为工厂被管理起来后一切都有文档，可以向它提问。主持人补了一句：耐心的导师、入职伙伴。正是如此，入职不再是在别人脑子里的隐性知识里打捞。做智能体编程时，要把任务切小、确认真正做完，并需要“批评/检视”。他一直担心：如果只有一个模型家族，其对齐问题可能变成你的问题，所以要用另一个模型家族来做检视。这像从手写汇编走到编译器：意图到代码的抽象层变了，团队协作和产品构造方式也变了。他特别兴奋生产轨迹回流：能把生产日志拿回来验证修复，再一路部署并确认通过全部测试——这就是他心目中的 RSI（递归自我改进）版本，即可验证闭环。这些做法正在微软内部铺开。他最喜欢的故事之一是 Azure 网络团队：微软在全球管理大约 500 个光纤运营商，物理资产总会出问题，所谓 DevOps 过去其实是邮件和各种临时流程；他们做了一套智能体系统来做运维，并且把运维接到代码仓库。技术团队开始建造的是“运维 + 软件”的工厂：让工厂去完成工作，而人做的是另一种略有不同的工作。

  6. 6棕地产品如何用上 AI，以及这次为何不同于引入 React查看原文 →

    格尔盖伊问：AI 实验室很愿意分享，那里工程师的工作变成“让循环里的智能体把活干得更好”；但微软这样既有赚钱产品、又有真实客户的公司，总不能放下一切去造工厂。纳德拉先划线：没有许可去做不能给客户增加价值的事。他们也犯过为了“酷”而做随机 AI 功能的错，几乎每家公司都做过，他本人也有过，希望已从中学习。然后谈棕地现实：今天 Windows 的 CVE，因为已有 AI 模型在找漏洞，他们必须全部修掉，于是出现新的流水线；Windows 从崩溃轨迹到修复，也在长出一种新的软件工厂，但 Windows 的构建系统还是原来的构建系统。棕地项目最难的往往是构建和 CI/CD。GitHub 亦然：编码智能体突然“来上班”，规模冲到超人类量级，他们必须改 Git 协议、改存储系统，从源代码管理到构建到 CI/CD 逐步加固。绿地项目会一直做，但真实世界是棕地，操作顺序极其关键。他希望的不是一小队人玩新工具、其他人留在旧世界，而是全公司——无论 Windows、SQL Server 还是云原生服务——都能用上新工具链，去解决自己面前的问题。格尔盖伊追问：这听起来和当年引入 React 差不多——没人获准停下来整体迁移，只是做新功能时掺进去。有何不同？纳德拉承认“似曾相识”，但觉得这次改变的是做事的“物理定律”：操作顺序和抽象层级。他大学时主要在 VAX 上用 VT 终端工作，那是大型机/小型机、VMS 的时代；后来在 Sun 做了几年工作站，再加入微软。此后职业生涯里，他大体都在 IDE 里写代码，新技术多是新框架、新运行时，概念数量并未根本改写；移动也大致是缩小的 PC 加新界面和新框架。而现在，运行时、框架、IDE、技术栈每一块都在变；而且随时可能再掉下一个前沿模型或决策引擎，把整套体制再次改写。既要向过去管理变革最成功的时刻学习，也要开放地承认“这次可能真的不同”。

  7. 7工程师的角色：专长没有贬值，变的是操作顺序与杠杆查看原文 →

    格尔盖伊说，对软件工程师来说最大的变化是：过去大部分时间花在写代码上，大学和前一份工作的训练也为此服务，而这一块突然不见了。以往任何技术变化都是添工具，而不是把核心技能抽走，这让包括他自己在内的很多人很难调和。在微软，员工里软件工程师或靠近代码的人可能占多数。纳德拉观察到，那些从前就是优秀工程师、如今在新生产模式下同样高产的人，需要的仍是同样的技能，变的是操作顺序和工具链。这不是贬低原有专长，而是让专长带上新的杠杆。行业正处在给新事物定价、同时反过来重新看见旧专长价值的阶段。他在上一届 GitHub Universe 遇到一批大学生，那是第一批在 AI 时代读完大学的毕业生——他们入学时已有 GitHub Copilot，根本不认识没有 Copilot 的 IDE 世界，这让他震惊。会有原生适应这套工具链的人进来；但在微软，凡是在自己领域有深度、保持好奇心、并学习新工作方式的人，都在其中茁壮成长。归根结底，职业上要看经济回报；他希望员工既能珍惜已有技能，也能培养市场会定价的新技能。

  8. 8自愿退出方案：给 20 万人更多能动性，而不是假装一切不变查看原文 →

    格尔盖伊直接抛出开发者圈的猜测：微软为何推出从未有过的自愿退出方案？会不会是 AI 让团队更高效之后的裁员前奏？为何是自愿的？纳德拉说这是非常重要的问题。他们内部讨论后想先承认：未来机会仍然很多，但机会的形状会变——即使只看软件工程也是如此。下一步是在公司内部创造更多新机会，无论做 Windows 还是做 AI 训练，都要能装备起在微软和市场都值钱的新技能。但新事物的形状不同：团队规模、工作流都会变。他希望约 20 万名微软员工都能成长，但这 20 万人必须以不同方式被配置。系统工程师、基础设施人员的薪酬已经高得惊人，做训练的研究员同样竞争激烈、被高度定价。自愿方案主要是给每个人更多能动性，把自己配置到对长期经济机会更合理的位置。他从个人贡献者一路做到 CEO，会用“若我是 IC 或组长，会希望公司怎样给机会”来想这件事：他不愿被困在一个没有转型的团队里，也不假装微软每个角落都已经按他想要的节奏拿到通知并完成转型。若你在团队里感到职业停滞，应该能用脚投票；他其实更希望你走进微软内部其他许多去处。这是一段动荡期，他不能说一切如旧，只能尽量透明，并做创造机会的苦功夫。格尔盖伊把它翻译成更直白的话：世界变了，Claude Code 这样的变化来得极快，团队不能在方向盘后睡着。要么跟上、对工厂和新工作流感到兴奋，要么选择不跟上；多数地方你会卡住，而微软现在给了一个没有恶感的“现在可以离开”的选项。纳德拉同意，并强调舆论从“奇点已到”“以后没有工作”一路讲下来，给人们制造了巨大焦虑，让人觉得无法掌控自己的命运。微软有 20 万人，每个人的工作都会变。他指出，微软增长最快的岗位之一是驻场工程师（FDE）；旁边还有客户成功（他称为 CSU）和技术支持。这些角色都该去上软件工程师在上的那种 Perceptorship。LinkedIn 内部甚至把角色合并，称为“全栈构建者”（full stack builders）。机会在，但必须做组织重构的苦活：把人配置到位、给机会、给薪酬支持，并学会在新岗位上评价生产力和卓越。微软是一家 51 岁的公司，要在自己的皮肤里自在，服务好客户，并为员工创造经济机会，履行赋能每个人和每个组织的使命。

  9. 9初级招聘放缓：先建好新工厂，再下长期结论还太早查看原文 →

    有人担心：最能发挥 AI 杠杆的是已有专长的人，因此很多公司放缓甚至停止招应届生和初级员工。纳德拉说，趋势要纵向多看几年，而不是只看一年。眼下第一件事是把内部的人重新配置到合理位置，连团队内部都要先把“配置”做对，然后再谈行业招聘或应届招聘。放缓，可能是为了先把那些新的软件工程工厂建起来，好让新的输入——不只是 token，还有人——能在新配置里获得高杠杆。AI 原生公司往往从一份 token 预算加一个人开始，等这个人把 token 预算用到尽，再加下一个人、再给一份 token 预算，工厂再拿到预算。这就是那种从零搭建的方式；成功的那些公司有的已经很大，将来每家公司、每个产品团队都会开始像这样。重新发现和重新配置需要时间，现在就画太多长期趋势线，还太早。

  10. 10开放权重模型，以及企业必须握住自己的模型系统查看原文 →

    许多科技公司在转向开放模型，自己做推理，或像 Revolut 那样买推理、买 B200，把模型跑起来。微软也通过 Foundry 做开放模型服务。这趋势有多大、是否不可避免？和开源运动是否平行？纳德拉认为确实有平行：会有封闭模型之间的竞争，开放则是替代方案，带来灵活性。关键问题是前沿生态系统长什么样。如果你不相信会有一个装下世界全部知识的前沿模型，那就得假定有多少家公司就大致该有多少个前沿模型。他引用哈耶克对经济的描述：知识是分散的、默会的，价格机制之所以成立，正因为知识分布在经济各处，每家公司都需要掌控它。由此，每家公司都将同时拥有人力资本和 token 资本。token 资本可以是嵌入了公司知识的开放权重模型；也可以放在上下文层；甚至可以同时用多个封闭模型，收集使用轨迹，再用来训练自己的小模型或开放权重模型。GitHub Copilot 和 Copilot 都被设计成多模型系统。他预计下次再谈时，人们将不再争论开放还是封闭，而是谈论“模型系统”：先有一个决定“哪个任务用哪个模型”的决策引擎，再把上下文、记忆和动作空间与任何一个模型分开，否则就是彻底锁定。如果编排（harness）、模型、记忆全部耦死，你还怎么出去？模型会把看见的一切吞进自己里面。这不只是科技圈的竞争：智能没有上限，银行、医疗、保险、分析师，每家都要有架构方法来掌控自己的学习与知识、形成公司差异。开放权重模型是其中一条走得通的策略。格尔盖伊说，他接触的大量中型科技公司和创业公司几乎都在自建编排、上下文层、上下文图和推理；他起初以为只是工程师爱做内部项目，现在听来他们可能恰好做了战略上该做的事。纳德拉确认：银行应该看看那些想成为“前沿”的软件公司怎么做——他们不会交出控制权。微软把 Copilot 和 GitHub Copilot 底下的编排做成一等公民，作为托管服务放到 Foundry，叫他们说的 IQ 层。做供应链系统时，可以用微软这套自己也在用、经过实战的编排，也可以接入 Pi 或其他开源编排。然后可以在 Foundry 上接多个模型端点，上下文和记忆完全分开，插件、技能、连接器构成的动作空间也不属于某一个模型。一条经典的中间层平台正在为“模型优先”的开发出现，这样你才不会被俘获，并且可以做评估：对你重要的是私有评估，而不是只有公开基准。客户常常先用前沿模型，收集轨迹后把流程变成更确定的工作流，再为了成本优化换上 MAI Flash 一类模型、用轨迹微调。这些都可以在 Foundry 里做。很多公司还在评估之上自建强化学习环境，以便控制价格，也避免业务数据泄漏给可能用来训练的 AI 公司。纳德拉用关系数据库作类比：你可以部署数据库、再扩展自己的业务逻辑，但数据不会因此跑到别人那里；即便厂商不再提供更新，你仍可迁走。那么，如果你的记忆已经写进某个模型的嵌入里，当那家模型公司说下一次更新没了，你怎么把记忆迁出来？若过度依赖某个或某几个厂商，新原语出现时你只能等他们。他认为有两项企业架构决策会越来越被讨论：一是避免他所说的“逆向信息悖论”——不要泄漏你的价值，公司必须掌控自己的学习回路；二是让上下文与模型分离、编排与上下文和模型分离、同时使用多个模型，这是你能保证自己换得掉任何模型的唯一办法。他的酸检测试是：你应当能替换任何一个模型，并且仍然能在自己的私有评估上爬坡。做不到，就要问自己还算不算一家有主权的公司——那意味着你没有控制自己的产出。主持人说，那简直是坐在一颗滴答作响的定时炸弹上。

  11. 11信任架构、本地模型与混合智能，以及微软的模型策略查看原文 →

    纳德拉说，接下来需要信任架构。扩展定律有效，但扩展带来的是新能力，不是对齐；目前也没有机制层面的理解，只希望将来有科学突破。眼下的危险位置是：模型越来越强，却越来越不可靠。因此必须在架构上把权威和智能分开。如果不可靠的智能拥有权威，你就等于有了巨大的内部风险。智能体必须按内部风险来对待，要有信任系统。思维链不能是“神经语”（neuralese），必须是人类语言、可审计、可记录、不能被篡改；不仅预训练和强化学习里会出问题，测试时计算也可能出现奖赏黑客。必须在运行时建立大量保障，把模型和智能体当作内部风险来监控，同时保持对学习回路的控制。格尔盖伊作为工程师听到的是：有大量尚无蓝图的新系统要建，也许要五到十年才会有蓝图和认证，眼下这就是工作本身。纳德拉说下周就是 Ignite 大会，他希望讲清楚：这些是可做的，已经有蓝图和创新；不能只停在新鲜感上，而要坐下来问如何为公司创造企业价值，成功模式才会更清楚。格尔盖伊转向本地模型：现在模型要么跑在别人的云上，要么要买他或公司负担不起的 B200，为什么不能跑在笔记本电脑上？本地 AI 一直很黑客、很难用，而微软正在创新——斯科特·汉塞尔曼给他演示了新的 Surface Ultra 笔记本，上面有芯片、能跑本地编码模型。纳德拉很兴奋在 AI 时代继续把 PC 这一形态做下去：分布式计算始终是分布式的，为什么只用云里的 token，而不用已经散落在各处的算力？这是 Ultra 的灵感来源之一。NVIDIA、AMD、高通、英特尔都在做很好的芯片和系统工作。已经出现这样的情况：去年的前沿可以在笔记本上跑，上个季度的前沿可以在桌面上跑——就像当年 PC 能力的演进。然后是路由：他先提到 Hydra Fusion，随即和主持人一起落到 GitHub 的 Copilot Fusion——按任务挑选模型。在 Ultra 上他有时会听到风扇转起来，因为本地模型被用上了；尤其在智能体群、有多个子智能体时，一部分子智能体可以调本地模型，同时仍用云端模型。这在架构和经济上都说得通。云仍会增长，对 token 的需求近乎无限，但端侧形态也可以成为 token 工厂。他称之为“混合智能时代”，以及“不计量的智能”——你不必担心用了多少。格尔盖伊说，他对 MAI Code 的 Flash 1.1 模型并不太满意，觉得几乎没人特别满意；但有一个细节打动了他：他本以为能在任意笔记本上跑的本地模型必须是开放模型，而 MAI Code 虽是封闭模型，却可以下载到 Windows 机器上跑，基础设施已经在。是否会出现一个未来，封闭模型也可以被下载到笔记本上，免费或只花很少钱、由用户挑选？纳德拉说，把代码 / Flash 类模型一直做到笔记本上，是他们的核心优先级。在 Copilot 的代码标签里——即使独立于 GitHub Copilot——写文档或写应用，也可以在 PC 上使用这些模型。再看 MAI 模型策略：通过与 OpenAI 的合作，他们会继续使用 OpenAI 模型；在此之上，再从零创新一个新的模型家族。“从零”意味着自己做预训练。他们披露了新的 MAI-2 Base，那是一次预训练，也被外人称为对预训练配方和制度最详细的披露之一，相当于一次洁净室式的预训练实现。他们要在前沿曲线上用自己的产品——网络与安全（cyber）、知识工作、编码——标出新的点：训练端要省 FLOPs，部署端要省 token。当高阶意图被交给许多子智能体时，子智能体可以使用多个模型家族；他不认为必须从一而终绑死一个家族，智能体会聪明地选出最有效完成任务的模型。他们的目标是给更多选择，而不是只推一个模型家族。

  12. 12给工程师的建议：少追标题，回到动手与“上学模式”查看原文 →

    作为收束，格尔盖伊问：变化又快又大，纳德拉经历过多个周期，若目标是在一两年内成为这个 AI 新时代里出色的软件工程师，该如何面对？纳德拉说，先把自己安放在“这场变化到底是什么”上，而不是标题和炒作周期——他喜欢 X，但那不够。主持人说，还要抵抗那种不断“说”的冲动；在播客里这么讲有点讽刺，但就是要多做、多学、要有亲手经验。纳德拉说，如果他能改变自己“说与做”的比例，他会改；无论你是中年职业者、像他这样的 CEO，还是刚毕业的学生，都该尽量走进正在做的团队里学习。他问自己何时状态最好：是进入“上学模式”的时候。所以，回到学校去。主持人致谢后收束：当编码因 AI 变便宜，编码之前的规划与之后的验证都会更重要，工程师会把更多时间花在这些活动上。很多科技公司在自建编码编排、上下文层和 AI 基础设施，他本以为只是工程师爱玩新东西；纳德拉指出，一家公司如果不掌握自己的 AI 基础设施和 AI 知识产权，策略上近乎自杀。成功的公司都会长出自己的 AI 基础设施，只靠单一厂商或实验室是重大战略错误。对开发者而言，这类新基础设施和内部软件工厂意味着大量建造机会。工程角色也在变：微软内部增长最快的岗位之一是几年前还不存在的驻场工程师。纳德拉预计微软会有很多重组，团队变小、角色改变；自愿退出方案是给那些不想经历接下来这段比以往更剧烈的变化的人一个选择。这种重组和角色变化的强度，大概不只发生在微软，也会发生在许多科技公司。他离开时反而更有能量：有大量软件工程工作在等着人们用决策模型等新原语——以及尚未发明的原语——去建造新系统，决定什么放在哪里、如何改、如何部署，并持续从中学习。他提醒观众查看节目注释里关于评估、推理工程、循环工程等的深度文章，并欢迎订阅和评分。

纳德拉

我也还在摸索。我是在对今天软件团队里一群人在做什么做模式匹配。我会建议观众去看巴斯（Bass）写的那篇博客。其实有两篇都很好：Copilot Cowork 团队和 GitHub Copilot 团队都发过。一篇讲的是，在 GitHub 那边，一名开发者能够做到什么——他维护了整套运行时，而且我记得他们还做了迁移，我忘了是不是从 Python，我猜是迁到了 Rust。

棕地产品如何用上 AI，以及这次为何不同于引入 React

Gergely

对，我的意思就是这样。接下来，你现在需要一套信任架构。也就是说，在一个你已经知道扩展定律有效的世界里，扩展会带来新能力，但不会带来对齐。事实上，目前也没有机制层面的理解——当然希望有一天会出现科学上的突破——但眼下我们得到的是越来越强的能力，以及越来越低的可靠性，而这是最危险的位置。所以你必须在架构上把权威和智能分开。如果你的智能拥有权威，而它又不可靠，那你就麻烦了：你有一个巨大的内部风险问题。所以你必须把这些智能体当作内部风险来对待，这意味着你必须有一套信任系统。

这里要做的事情很多。即便是思维链：思维链不能是神经语（neuralese），必须是人类语言，必须可审计、必须被记录，并且不能被篡改。不只是在预训练或强化学习里会出问题，在测试时计算里也可能出问题，因为它们可能做奖赏黑客（reward hacking）。所以我们必须在运行时建立大量保障，也就是我所说的信任架构：确保你可以把模型和智能体当作内部风险来对待，去监控它们，拥有可观测性，并确保你对自己的学习回路保持控制。

Gergely

纳德拉

没错。事实上，我们下周就有 Ignite 大会，我对此感到兴奋，因为我希望我们能把这件事讲清楚：这些都是可做的，已经有蓝图，公司在这些方法上也有大量创新。我认为我们正到达这样一个阶段：不能只停在那个闪亮的物体和新鲜感上。人们必须坐下来问：我怎样在自己的公司里创造企业价值？一旦人们把这件事谈得更深一点，这些成功的模式就会变得清楚得多。

Gergely

再作为工程师说一句，我感觉非常缺的一件事是：所有这些 AI 模型，要么跑在云上、跑在别人的服务器上，要么跑在我买不起、或公司不会为我买的超昂贵的 B200 上。如果你幸运倒也罢了，但若它就能跑在我的笔记本电脑上，岂不是很好？到目前为止，本地 AI 一直很难、非常黑客。有意思的是，正在这里创新的反而是微软：有一款新的 Surface Ultra 笔记本电脑，斯科特·汉塞尔曼给我做过演示，我现在特别想亲手试试，因为它有一颗芯片，上面跑着本地的编码模型。你认为本地模型在这个 AI 循环里应处在什么位置？作为开发者，我觉得这是非常缺失的——但我是不是少数人？你和远比我多的人交谈。

纳德拉

就像当年 PC 演进的方式。

Gergely

纳德拉

一旦你进入把高阶意图交给许多子智能体的世界，这些子智能体就可以使用多个模型家族。所以那种“我必须从一而终绑死一个模型家族”的想法，在有选择的时候可能并不成立：智能体会聪明地挑选所有能让它们以最有效方式完成任务的模型。我认为这就是我们的目标。我们的目标是给出更多选择，而不是只有一个模型家族。
