一句话概述

Latent Space 对话 Linear 首席运营官克里斯蒂娜·科尔多瓦（Cristina Cordova）。她在约 40 人、产品驱动增长仍占主导时加入，用工作试用做出六到十二个月的走向市场计划，先把「立即进攻企业级」的目标划掉，改为拿下成长段客户，直到 2025 年才建起企业销售。面对卡里·萨里宁（Karri Saarinen）「问题跟踪已经死了」的判断，她把公司转向智能体工作流：2025 年率先推出 MCP 服务器，约一年半后超过一半的问题由智能体创建，同时坚持自建支持、不设销售发展代表，并在仍有 4 万付费客户、长期按席位计费的基础上试探用量定价。字幕未出现主持人姓名。

核心要点

  • 她在 Linear 约三年半，加入时约 40 人，当时还没有上市公司客户、单个客户大概不超过约 500 个席位，Vercel、Ramp 等主要靠自助注册成长；她称加入以来规模至少已增长十倍。工作试用的课题就是未来六到十二个月的走向市场计划，而且就是入职后的真实工作。
  • 早期市场动作几乎只是更新日志邮件（订阅不到 10%）再加推文；销售在试用时只有一人，此人现在已是销售负责人。公司不设销售发展代表，也不做前线派驻工程师，坚持不外包支持——她明确指出 Stripe 的支持是外包的——因为在没有销售团队的很长时间里，支持往往是客户的第一接触点。
  • 入职约三周的外拓会上，她当着当时约 35 到 40 人的面，把「进攻企业级」的公司目标划掉，改为先赢下需要拆掉旧工具的成长段客户；2023 年加入，直到 2025 年才组建企业销售团队。

  • 公司有 4 万付费客户，直到今年 6 月历史上完全按席位计费，现在部分新功能按用量收费：智能体聊天免费并使用前沿模型，编程会话可在 OpenAI 与 Anthropic 之间选择并按公布接口费率加一点加价。支持由人工智能起草、必须由人发出，拒绝「100% 先由模型回复」。
  • 2025 年本是进攻企业级的一年，但 MCP、智能体平台以及与 Codex、Cursor、GitHub Copilot 的合作都不在原计划里，一批企业级功能因此延后。公司现在约 170 人，除创始人和她以外没有其他 C 级高管，更倾向扁平结构和「负责人」头衔。

  1. 1开场介绍，以及为何在约40人时就招首席运营官查看原文 →

    节目以冷开场切入：Linear 首席执行官卡里·萨里宁（Karri Saarinen）写了《问题跟踪已经死了》，主持问该如何向客户解释。克里斯蒂娜·科尔多瓦（Cristina Cordova）说，公司还没有大到会「把自己废掉」，不像谷歌（Google）很难亲手削弱搜索、在结果顶上放人工智能框后广告可能没人看；死掉的是手工跟踪工作，不是问题（issue）这个单位本身。客户的反应往往是：对，跟踪已经死了，那我现在买的到底是什么？随后正式介绍：她在 Linear 约三年半，加入时就是首席运营官并一直任职；此前在 Notion 负责平台，搭建应用程序接口、合作伙伴和自助增长；再往前在 Stripe 待了七年半，先做早期合作与走向市场，后转到产品侧为早期公司做新产品。主持问为何在约 40 名员工时就招首席运营官。她并不认为每家公司都需要这个角色，常劝刚找到产品市场契合的创始人先别急着招她这种人；若只是创始人已没法亲自卖掉每一个新客户，应先招销售或销售负责人。Linear 三位创始人在设计、工程和产品上很强，但商务侧放大时，他们说不清下一个销售该长什么样、怎样算做得好；当创始人还不知道「出色」长什么样时，才适合引入像她这样的职能负责人。

  2. 2加入时的盘面：中型市场、产品驱动增长，以及真实的工作试用查看原文 →

    加入时已有一些大客户，但还没有上市公司客户，单个客户大概也没有超过约 500 个席位，天花板基本在中型市场；外界更熟悉它适合创业公司。当时产品驱动增长走得不错：多数人自助注册后跟着一起长，Vercel、Ramp 等客户几乎从未跟 Linear 的人对过话。与此同时，也到了该卖给另一种公司的时候——不签合同、不做试点、不先调研，就不会往服务里放数据。她说至少从加入到现在，规模已增长十倍；入职时间是差不多三年半前，不是四年。加入前她也做了工作试用，课题就是未来六到十二个月的走向市场计划，而且就是入职后的真实工作，不是虚构项目：若试用结果不被认可，就不该聘用。她当时向已有的一位销售、客户成功、支持和一两名市场同事征求一线意见，把优先级和愿景对齐，入职时几乎已有一份小蓝图。

  3. 3早期走向市场：让品牌变得不可避免，以及坚持自建支持查看原文 →

    试用计划很多是品牌和市场向的，目标是让 Linear「不可避免」：要么已经在用，要么就该在规划迁过去；当时知名度主要还在特定圈子。所谓市场动作几乎只是发更新日志邮件，订阅用户不到 10%，大多数人甚至不知道新功能，再加上创始人或公司账号发推再转发。她于是转向在用户每天所在的应用里做通知，并开始组建销售。产品驱动增长只能带到某一个点；对产品研发如此核心的系统，很多公司没有跟真人建立信任就不会下单。试用期间销售只有一人，此人现在已是销售负责人。公司没有销售发展代表，也不做前线派驻工程师，后来才加上与之不同的解决方案工程师。早期优化的是招有技术产品销售经验、向设计师和工程师卖过东西的客户经理，因为这类买家要看演示而不是精美幻灯片。创始人面试时明确不想外包支持；她以前待过的公司没有一家不是外包的。主持以为 Stripe 自己做支持，她纠正说 Stripe 虽有内部支持人员，但支持是外包的。因为很长一段时间没有销售团队，客户第一接触点往往就是支持，所以必须做好；至今已扩成完全不外包的全球团队，只要仍可行就希望尽量维持。

  4. 4先把企业级目标划掉，2025年才真正进攻大客户查看原文 →

    她加入时公司有三个公司级目标，其中一个是向上进入企业级。入职约三周的外拓会上，她当着当时约 35 到 40 人的面，把「去拿企业客户」那一条划掉：销售只有一个人，不具备能力、学习和资源。当时赢下的多为自己长成成长段或中型市场的客户，并不是大量新获取中型公司。她把目标改成拿下成长段、说服对方拆掉已有工具再换成 Linear；若这件事能做成，才有信心在一到两年后进攻企业级。她用 Stripe 类比：先赢的是第一次上支付的新业务，切换者是后来才拿下的；拆掉已有技术再替换，和叠加一个新产品是完全不同的销售。她 2023 年加入，直到 2025 年才在全公司宣布今年要做企业级，并建起企业销售团队。早期说服客户切换，不能只好 20% 或 30%，因为有切换成本；创始人在 Coinbase、爱彼迎（Airbnb）、优步（Uber）用过那些老工具，知道没人喜欢。早期重心因此放在设计和用户体验，但人们必须先试用才会懂。策略上做得好的一点是先提供免费产品，用量到上限再付费，许多人是先自己试用再带到公司。

  5. 5「问题跟踪已死」：MCP、过半工单由智能体创建，以及新品类查看原文 →

    现在的卖法已转向过去一年半到两年的剧变：发现缺陷、手工填报、打标签、指派、修复、更新状态再通知客户，整条链路都是手工，不再说得通。公司把重心转向让智能体承担那些其实不算「做产品」的环节，让工程师、产品经理和设计师把时间用在真正做产品上。她不认同「自己只当数据库再加一个 MCP 服务器、把数据交给外部智能体」会是一门好生意，必须把智能体工作流做进自己的工具并做得更好，否则人们没有理由再进入产品。Linear 在 2025 年推出 MCP 服务器，她认为是该赛道里第一家；大约一年半后，超过 50% 的问题由智能体创建，同时进入应用创建或集成问题的人数也在明显上升。聊天界面往往不适合查看团队全部工作，且多为单人模式；只要 MCP 使用量和应用使用量一起向右上方走，就说明对人和对智能体都好。最小工作单位仍是问题；循环（Loops）可自动把问题指派给智能体开始写代码，他们希望看到的是 Linear 自己的智能体在干活，活跃度则看应用会话。面对卡里那篇博客，她再次用谷歌搜索与广告的类比谈创新者窘境：要做的是一套减少手工劳动的产品研发系统，开辟新品类，把绝大部分资源投向智能体编排，同时仍参与旧品类。

  6. 6前沿实验室在推、传统企业在跟：接口、分诊智能和销售认证查看原文 →

    那篇博客并非突然袭击，团队是对齐的。一部分客户确实在要这些能力：绝大多数前沿人工智能实验室和顶尖人工智能公司已在用 Linear，Linear 出现之后创办的公司明确表示，若产品不往智能体方向走，就不再合适。与此同时，Ramp、Coinbase 这类在人工智能出现之前就存在、却仍处在前沿的公司，正自建内部智能体并希望掌握专有数据，需要能在 Linear 里创建智能体并深度集成的应用程序接口；当时竞品还没有这样的系统。有些客户在要，很多当时并没有要，但现在不少人很高兴这些功能已经存在。正在推进的企业客户更多是偏传统的公司，不是最初把他们往这个方向推的那批，但现在这些公司也会主动找上门，要求底层工具集像编程智能体格局一样快速进化。教客户使用新功能时，销售和客户成功必须把产品吃透，通话会用 Gong 录制，客户常把工作流投屏分享；有构建者、尤其是人工智能实验室当客户，要向他们学习再打包给还没走到那一步的用户。由此做出分诊智能（Triage Intelligence）：缺陷报告、功能请求等进入分诊后自动打标签、指派并进入正确团队队列，人不必自己再造一个智能体。她强调 Linear 谁都能用，不像 GitHub Issues 会让非工程师感到「不该待在这儿」，因此能在销售、运营等团队墙到墙铺开。销售须通过课程认证才能独自见客户；最复杂的是代码审查产品和 GitHub 集成。现在销售会直接提交网站文案修改，市场同事也会改数据存储以服务收入运营，工程师负责审查批准。

  7. 7编制保持精干：不设销售发展代表，支持由人把关查看原文 →

    外界常谈团队会变得更小、更扁平，但她见过很多公司先这样、人一多就长「出去」。Linear 在这些变化发生时本来就如此运作并维持了下来。他们从未设销售发展代表，信念是销售应自己写得出外拓邮件。这类角色通常负责外拓或资格筛选，第一通电往往只问规模和预算，客户会讨厌浪费三十分钟才能见到能做演示的人；他们选择用系统、工具和自动化，让客户经理自己做感觉定制、真正有用的外拓。客户体验上，会用工具自动起草回复，但人是质量把关，不会让人工智能批量发出，也不接受「100% 先由大语言模型回答、只有客户生气才转人工」的模式。人工智能常把三句话写成三大段；外界有时因回复极快而以为是人工智能，其实是团队很快，也常有人说这是很久以来第一次遇到好的支持体验。她澄清不是在裁客户体验编制，而是没有工具时本来会扩得更快，不必让人数与业务增速线性增长。市场侧会用人工智能转写客户访谈并抽取要点，但故事仍由人来写，因为他们不喜欢很多人工智能写作的味道，希望品牌仍是定制、手工打磨的。

  8. 8解决方案工程师、迁移动作，以及四万付费客户直到6月仍按席位收费查看原文 →

    解决方案工程师是企业客户经理和成长段偏上客户的技术搭档，处理深度工作流、定制接口迁移，以及把三万人从老工具迁到 Linear 这类问题，对话对象几乎总是工程师。有人甚至通宵做出与 ServiceNow 的端到端集成演示，让客户看到迁移可以很快。他们通常不会以前线派驻工程师的方式进入客户系统去实施，哲学是 Linear 应简单到客户自己就能集成。竞品可以靠专职管理员去伺候几乎无限定制的工具；Linear 更偏专门打造、做事方式清楚，这对智能体也更好读——在别的工具里，「缺陷」这个标签对每个团队含义不同，数据很难辨认。销售还常帮内部倡导者向信息技术、采购等不每天使用工具的人做内部推销。成交周期没有统一法则：他们见过上千人公司由首席执行官自上而下拍板、一个周末就迁、大约一个月内完成；也见过花两年到两年半的，中间隔九个月再进来、再换人去说服首席技术官；有的则因当年预算已定，要等到 2028 年。她并不认为传统公司在这类决策上变得更快；真正解禁的是人工智能预算，把产品放进这笔很高、一度像凭空多出来的预算里，决定会容易得多。主持问这是否解释了有些人工智能公司三个月做到 1 亿美元收入，她说很多公司在签一年期或付费试点，而不签三年，因为变化太快。若被信任，他们有时也会签长期合同，代价是除非写好提价台阶否则三年不能提价，但能锁定承诺收入。Linear 有 4 万付费客户，直到今年 6 月历史上完全按席位计费，很难一夜从零到 1 亿美元；卖给国防或超大型律所、几单 3000 万到 4000 万美元年经常性收入就能到 1 亿美元的生意，形态完全不同。现在已有一部分功能按用量收费。

  9. 9用量定价怎么收，以及2025年把计划外的智能体排到企业功能前面查看原文 →

    很多软件即服务公司在转向按用量定价。大家都羡慕 Intercom 的 Finn 那种按结果收费的模式——人工智能回复一张支持工单就收一美元——但对「自动把缺陷分诊到正确团队值多少」这类并不清晰的结果，很难直接套用。她希望将来有说得通的结果导向模式，但目前主要按运行服务的成本收费：在 Linear 里跑编程会话，或让智能体把巨大的待办积压过一遍，成本可能很高，连聊天也可能更贵。因此他们让 Linear 智能体聊天免费，希望长期继续压成本；目前连聊天也用前沿模型，未来未定。编程会话可由用户在 OpenAI 或 Anthropic 的模型和配套框架之间选择，按公布的接口费率再加一点加价，尽量透明；循环则用人工智能积分。绝大多数人工智能功能直接做进产品、不必额外付费。按席位计费并没有消失，他们也没有把以前免费的东西改成收费，用量收费针对的是新功能。测试期内先免费使用并告知将来会收费，准备收费时提前通知；有时六个月测试期会让人五个月后才想起来要付费，除了产品内警示能做的有限。他们倾向一开始定得更贵再下降，而不是先过便宜再无法持续。回头看六到十二个月的走向市场计划，她认为该做的大部分都做了，只是未必都落在原定窗口里，销售也从几乎没有变成公司相当大的一块。2025 年本是进攻企业级的一年，路线图上有许多企业功能，但他们计划外地做了 MCP 服务器、供任何人把智能体做进 Linear 的新接口平台，以及与 Codex、Cursor、GitHub Copilot 的合作，一批为企业级工作区规划的功能因此没做完。她选择往前冲，并相信这会以不同于「子团队和跨团队路线图」的方式赢来新的企业客户；竞品等了很久，许多本来不会把 Linear 放进名单的企业因此把它放了进去。

我们当时赢下来的公司，多半是自己长成了成长阶段或中型市场客户，并不是我们新获取了多少中型公司。所以我把目标改成：我们要去拿成长段的公司。如果能赢下很多已经在用某种同类工具、必须被我们说服把旧系统拆掉再换成 Linear 的成长段公司，我才有信心说，一年或两年后我们可以去攻企业级。现在没有这份信心，为什么要把这定成团队的目标？

完全同意，就是要把小步迈扎实，先把今天能服务得极好的公司服务好。等更大的公司来做背景调查、问「你们喜欢 Linear 吗、体验怎么样」时，他们能说出非常正面的话，这才帮我们拿下新客户。我在 Stripe 时也很类似：很长一段时间里，我们并没有赢下多少从竞争对手迁过来的新公司；我们做得很好的，是拿下每一个从零开始做支付的新业务，也就是第一次上支付的创业公司。再往后，才开始赢下那些要切换过来的公司。有些事就是需要时间。

把已经存在的技术拆掉再换上，和在现有系统上再卖一个又新又亮的东西，是完全不同的销售。知道自己处在非常类似的位置，我就重要地把团队对准一个我觉得「可解」的问题。我是 2023 年加入的，直到 2025 年，我才再次站到全公司面前说：今年我们要去拿企业级。也是那一年，我们才启动企业销售这一段，并把那支团队建起来。

主持

所以你们先做中型企业。大多数公司本来就有问题跟踪工具，或某种类似的东西，你们得把他们从那套里「挖」过来。你怎么说服他们：我们在用某某产品，也还能用，但你来跟我讲讲看？【笑声】

克里斯蒂娜

早期靠的是：比现有替代方案明显好出一大截。我觉得只好 20%、30% 不足以让人切换，因为切换是有成本的。你得讲清楚，自己的产品为什么比已经「够用」、也已经拥有大量用户的方案更好。我们进入这个赛道的一个好处——也是 Linear 创始人选择这块的原因之一——是他们自己就用过那些老工具：在 Coinbase、爱彼迎（Airbnb）、优步（Uber）工作时都用过，知道没人喜欢那些工具。公司里一推广那些工具，大家的反应就是：「好日子要结束了，我们得开始用这些东西了。」

所以他们很清楚，竞品给人的那种感受是什么，也就更知道怎么做出一款能让人真正兴奋、愿意用来管理工作的产品。管理工作本身，按理说并不是一件让人兴奋的事。于是早期大量重心放在设计和用户体验上：做出一款人们每天愿意待在里面、也不得不用的产品。难处在于，人们必须先试用，才会懂；看几页销售幻灯片，是没办法「看懂」的。

我们在战略上做得很好的一件事，是让任何人都能先用起来：一开始是免费产品，用量达到一定上限后再付费。很多后来在公司里用 Linear 的人，其实是先为自己免费试用，感受到有多好用、比竞品轻松多少，再带到公司里。有一段时间，这条路走得很顺。

克里斯蒂娜

现在我们卖 Linear 的方式已经很不一样了。我们通常会跟公司谈过去一年半到两年这个领域发生的剧变：整套产品研发流程被掀翻了，做产品的方式完全变了，再活在那种全手工的世界里已经说不通——发现一个缺陷，再手动报到问题跟踪器里，再打标签、指派给另一个人，那个人再修、再更新状态、再关闭、再通知客户，整条链路每一步都是纯手工的。你跟大多数公司这么讲，他们都会说：对，完全同意。【笑声】

所以过去一年半，我们把公司真正转向了智能体（agent）：让智能体去承担工作流里那些其实并不算「做产品」的部分。我刚才讲的那整条链，都不是你在做产品。【笑声】如果能让 Linear 成为智能体工作流的好工具，那么使用它的工程师、产品经理或设计师，就能把更多时间花在真正做产品上，而不是为了证明自己在给公司增加价值，在系统里手工搬来搬去。

主持

这很有意思。因为早期的卖点似乎是用户体验，现在听起来，人好像都不怎么会跟界面交互了。

克里斯蒂娜

我其实觉得，现在很多公司感觉：自己只要当一个数据库，再加一个模型上下文协议（MCP）服务器，把数据交给智能体、让智能体跟自己互操作，就会是一门好生意。【笑声】我不认为那会是一门好生意。最终，你必须把智能体工作流做进自己的工具里，而且做得比人们在外部用来对接你系统的那些工具更好，否则人们没有理由再进入你的产品。

对我们来说，通常盯的指标在这里发生了很大变化。我们在 2025 年推出了 MCP 服务器，我认为自己基本是这个赛道里第一家做的。到现在，Linear 上超过 50% 的问题是由智能体创建的，只用了大约一年半。一半的工作，创建方式已经跟从前完全不同。这很能说明，短时间里变化有多大。同时，有多少用户进入应用、在应用里集成或创建问题，这条线也在明显往上走。

所以有时人们以为：我现在什么都用 MCP 服务器就够了。但你还是会回到应用里去交互，因为你需要把事情可视化出来；聊天界面往往不是查看团队全部工作的最好方式，对协作也不理想，因为它通常是单人模式。对我们来说，只要 MCP 使用量和应用使用量大致一起向右上方走，就能证明：我们既有对人很好的用户体验，也对智能体很好。这就是产品目标。并不是智能体出现了，你就可以不再关心界面。

主持

应用使用量是按使用人数来计的吗？我假设你们的客户基数也在增长，那你怎么衡量在应用里创建的工作？

克里斯蒂娜

我们最小的工作单位就是问题。如果你只看「创建的工作」，那就是一个人进入移动应用、桌面应用或网页应用去创建工作。再看工作如何在流水线里流动：被指派给一个智能体。有时是人手工指派，有时是一个智能体委派给另一个智能体。我们现在常常就嵌在工作流里。比如有一个叫循环（Loops）的功能，会自动把某个问题指派给智能体，让它开始针对这个问题写代码。很多时候是智能体在干活，但那是 Linear 的智能体，【笑声】这也是我们希望看到的。所以要看多个因素，不过要理解活跃度，我们一般还是看应用会话。

主持

这就回到卡里写那篇「问题跟踪已经死了」的博客。我猜他写的时候，你正好处在签一些合同的当中。【笑声】你怎么跟客户解释：我们整个生意以前就是问题跟踪，现在首席执行官刚发了这样一篇文章？这个转变是怎么发生的？

克里斯蒂娜

我们这门生意的好处正在于，还没有大到会把自己给废掉。【笑声】如果你是谷歌，要把搜索这门生意掐死，大概会非常难：在每条搜索结果顶上放一个人工智能框，可能就没人再看广告，整个商业模式都被掀翻。这有点像许多「人工智能出现之前」的工具所面对的创新者窘境（innovator's dilemma），我们也曾是那样的公司。对我们来说，好处是：看清世界在往这个方向走之后，要么带着「做出新时代最好产品」的计划一头扎进去，要么死守一个几年后大概不会再存在的时代。

如果我刚才说的那种每一步都要人手工介入的流程，将不再是我们所处的工作方式，那就得改。你现在看 Linear，问题这个单位当然还在，但我们大概不该再活在人人手工跟踪工作的世界里。死掉的是这个。所以博客发出时，我们跟各类客户聊，大多数人都说：对，跟踪已经死了，那你们是什么、我买的又是什么？于是定位更多地转向：现在要做的是一套产品研发系统。我们希望你把精力放在做出更好的产品上，并会做出一套让你几乎不用手工劳动就能做到这一点的系统。

这也是在说：我们要开辟一个新品类。在很多意义上，我们仍会参与旧品类，但团队绝大部分资源，会投向这个新品类——比如智能体编排，以及用不必大量手工把任务推过系统的方式来管理工作，无论是在 Linear 之内还是之外，都更智能体化地运转。

主持

销售发展代表通常是做什么的？

克里斯蒂娜

他们通常要么向外拓新的潜在客户、把他们推进管道，要么在客户进来时做资格筛选。他们会打第一通电，但那第一通对客户往往没什么用：代表只是在问你有多大规模、觉得能付我们多少钱。我们的客户会讨厌这种通话，他们会想：你为什么问我这些问题，你不是该给我做演示的吗？【笑声】我为什么要浪费三十分钟，才能见到一个能真正做演示的人？所以我们没有这个职能，既因为我觉得它对客户不合适，也因为你可以做出系统、工具和自动化，让客户经理自己去做那种感觉定制、真正有用、最终能走到某种互动的外拓。

这也许是我们跟其他公司的一个差别。我们也倾向于思考：业务的哪些部分可以用更少的人，哪些可以用工具去优化。客户体验团队就是一个很好的例子：我们可以用什么工具，自动起草给来信客户的回复？

主持

你不担心让大语言模型给客户写东西，会写出所谓的「人工智能垃圾」吗？这个问题怎么解决？

克里斯蒂娜

客户体验团队里，人就是质量把关。我们不会让人工智能批量发出去。很多别的公司可以那样做，这也完全没问题，不必苛责；但很多公司会说：进到支持团队的问题，100% 先由大语言模型回答，只有客户生气地回过来，人才会进来补一句「抱歉，让我给你一个真正的答复」。我们不相信那种模式。我更希望人工智能先根据已有知识，针对具体问题起草一个答案，再由人来判断这是不是一个好答案。

可实际情况常常是：这件事本来三句话就能说完，它却写了三大段，到头来也不是最有帮助的。我们在支持上收到非常多反馈：一种是，回复快到让人怀疑这是不是人工智能写的——其实只是我们团队真的很快，快到被人当成了人工智能；第二种是，好久都没有遇到过这么好的一次支持互动。对其他工具和产品来说，这其实有点悲哀。但对我们，这是我们经常给团队记功的原因之一：它会在客户生命周期很早的时候留下品牌印象；有时他们已经跟了我们好几年，第一次写信进来，也会因此更确信自己做对了选择。这些工具可以用，但我不主张盲目使用到损害品牌、让团队显得没那么有用、没那么懂行的程度——毕竟最终面对客户的，还是人。

主持

你刚才提到压缩客户体验团队的编制？

克里斯蒂娜

不是在裁员，而是我认为，如果没有这些工具，我们本来会把编制扩得更快。其中一些工具很有帮助，让我们不必总是让团队人数跟业务增速线性地一起涨。市场等其他部分也是一样：我们可以用人工智能工具把客户访谈转写出来，抽出最有说服力的片段，但故事仍由人来写。我们不太喜欢现在很多人工智能写作的味道，所以会用它帮我们从跟客户待过的两个小时里找出有意思的部分，但要让它感觉像 Linear 希望呈现的那样——定制的、手工打磨的——有些事就不该用这些工具，至少在它们变得更好之前不该用。【笑声】

那销售工程师在你们的销售团队里是怎么定位的？

克里斯蒂娜

我们称之为解决方案工程师，实质上是同一类角色。他们是企业客户经理、以及成长段偏上客户的搭档，会花很多时间和销售一起，处理客户非常深的工作流问题，或者客户在想：我在另一边用一套非常定制的接口集成了某个工具，迁到 Linear 该怎么做？对方问的是更深层的技术问题。又比如：我要怎样把三万人从一套老工具迁到 Linear？解决方案工程师会带着技术思维进来——他们都具备这种能力。

主持

他们对话的对象想必是工程师？

克里斯蒂娜

对，几乎总是。所以对方的问题会非常细。有时我们团队里的人会做出完整的端到端演示：你想看我们怎么跟 ServiceNow 集成？我昨晚真的把这个 ServiceNow 集成做出来了，现在演示给你看。这会让客户正在经历的迁移变得容易许多，因为他们开始看到：这些事情可以很快做成，迁移也没有那么难——这位工程师一天之内就做出了一个快速导入器。有时我们是在陪客户走这段路，但通常不会以前线派驻工程师那种方式进入他们的系统、拿他们系统的权限去实施 Linear。

这在很大程度上是一种哲学上的信念：我们相信 Linear 应该简单到别人自己就能集成。【笑声】有些竞品在客户那里有专门的管理员，整份工作就是管理那套工具，公司里有专职的「工具人」。对于几乎可以无限定制的产品，这没问题。但 Linear 不是那样，我们更偏向目标明确、专门打造的工具，产品里做事的方式相当清楚。

我也觉得，这会让智能体更容易理解。很多人从别的工具迁到 Linear：在那些工具里，「缺陷」作为一个标签，对这个团队是一个意思，对另一个团队又是另一个意思。之所以能那样，是因为不同团队可以完全按不同方式工作，但代价是数据变得很难辨认。我们的系统正因为这些特点，对智能体来说更好读、更好理解、更好协作。再加上销售身边有一个技术搭档，这个组合很重要。

我们的销售经常对接的是公司里的一位内部倡导者：他们会说 Linear 非常好，可我说服不了另外那个人，你能帮我吗？对方可能是信息技术、采购，或其他并不每天待在工具里的人，往往也不理解那些痛点。我们的销售基本上就是在为这个人代言：我能做些什么，帮你在内部把这件事推销出去？工程师往往不习惯「我还得向公司里的其他人推销这套工具」，这是一种可以学习的技能，我们常常能帮上忙。我们的销售会处在一种挺有意思的位置上，通过其他人来为 Linear 做倡导。

主持

我有点好奇，遇到这种必须找到有决策权的人才能成交的情况，你们有没有经验法则，大概要多久客户才会真正下单？从那位内部倡导者出发的话。

克里斯蒂娜

有时一个决定可以从一个人开始，我们见过。然后他们获得首席执行官的支持，首席执行官直接做自上而下的决定：这个周末就迁到 Linear，适应不了就离开。决策方式非常专断。这类决定可能一个月内就发生。我们在一家上千人的公司就遇到过这种情形。如果首席执行官是那种风格，事情可以很快。我自己不太是那种人：如果觉得团队该用某个工具，我会说你们自己评估、自己决定。每家公司运作方式非常不同，你必须考虑特定组织里的政治——每个组织在某种形式上本来就都有政治——再想办法把这个决定推向对你的生意有利的方向。

我们也见过大概花了两年、两年半的公司。而且不是他们一直待在销售管道里：进来一次，说说服不了首席技术官；大概九个月后再进来，开始在公司里用；再过九个月，换了一个人进来说，现在也许能说服首席技术官了。就是要花非常长的时间，才终于得到批准、做出决定。有时是预算：今年预算已经定了，如果这还要增加支出，那就得等到 2028 年再决策。有些公司就是这样运作的。

主持

你有没有看到，因为现在变化这么快，他们决策也更快了？还是没有，尤其那些更传统的公司？

克里斯蒂娜

说实话，至少在这类决策上，我不觉得他们变得更快，尤其是更传统的那些公司。对很多这样的公司，真正让他们加速的，是人工智能工具基本上被「解禁」了。如果工程团队相信这套工具会让他们变得更好，而它又能放进公司的人工智能预算里——这笔预算也许不是无限的，但非常高，而且一度像是凭空多出来的附加预算——那事情就好办得多。这种情况已经开始变化；但在很多意义上，只要你能把自己放进那笔人工智能预算里，你就打开了一笔以前根本不存在的预算，公司做决定也会容易得多：哦，有预算了，我们神奇地找到了以前没有的预算。

主持

所以你觉得，很多人工智能公司能在大约三个月里做到 1 亿美元收入，就是因为这个？以前很多公司没有预算去试新工具，现在却觉得「天哪，再不试试这些工具公司要完了」，【笑声】于是先实验，也许一年、两年后这种窗口就会关掉？他们现在在试，之后会弄清什么真正有用、什么没有。

克里斯蒂娜

我觉得很多公司确实在实验。你可能签的是一年期合同，或带费用的试点协议，但不会签三年期，因为你也不知道两年后自己还会不会喜欢，事情变得太快了。

主持

对一家公司来说，签三年期合同正常吗？

克里斯蒂娜

如果你被信任，我们有时也会因此签很长期的合同。这里有取舍：除非协议里写好了提价台阶，否则那三年里我们不能提价，【笑声】但你锁定了承诺收入。对公司那边也一样，他们可能拿到一个否则拿不到的三年折扣。不过回到你举的例子，我觉得那些生意在客户上非常集中。像 Linear 这样、有 4 万付费客户、而且直到今年 6 月历史上完全是按席位计费的生意，很难在一夜之间从零长到 1 亿美元。你若是卖给国防工业，或卖给超大型律所，签下几单 3000 万到 4000 万美元年经常性收入的合同，好，我们就到 1 亿美元了。某些类型的生意更接近那种形态。

主持

那你们怎么说服客户，从按席位计费转到按用量计费是件好事？这件事难吗？

克里斯蒂娜

软件即服务（SaaS）世界里，很多公司确实在转向按用量定价。大家都希望能有类似 Intercom 的 Finn 曾经长期存在的那种模式：如果人工智能回复了你的支持工单，那就收一美元——你是在为促成的结果定价。可是，每一张被回复的支持工单都值一美元吗？【笑声】对其他类型的生意来说，要难得多：自动把这个缺陷分诊到正确的团队，到底值多少？也许每家公司都不一样。有的公司会觉得，那本就是产品经理的工作，他们就该把缺陷分到正确的队列、交给正确的人；另一家公司则希望产品经理把时间花在跟客户谈话、做产品路线图和其他事情上。在那些结果导向并不那么清晰的职能里，按用量怎么收费，有时会有争论。

我当然希望将来能有一种说得通的、基于结果的模式，但不知道现在是不是已经有。【笑声】所以目前我们主要还是按运行这些服务所发生的成本来收费。有些情况下这些成本相当高：如果你在 Linear 里跑一个编程会话，或是让它把整个待办积压过一遍、告诉你接下来该做什么——积压可能非常大。即便只是向智能体提出聊天问题，也可能更贵。有些事情我们决定做成免费的，比如 Linear 智能体的聊天对话是免费的，我们觉得长期还可以把这部分成本继续压下去。

主持

你们那部分是在用开源模型吗？

克里斯蒂娜

现在用的是前沿模型，连聊天也是。未来会怎样，还不好说。【笑声】再往后，你在 Linear 里开编程会话时，目前可以在 OpenAI 或 Anthropic 的模型和配套框架之间选，最终由用户决定。我们的收费方式基本上是：这是接口向我们收的价、这是公布费率，我们再在上面加一点点，就这些。对大多数用户来说，尽量说得清楚、透明。像循环这类产品，我们还有一套人工智能积分模式。其他功能会再有些不同。我们绝大多数人工智能功能是直接做进 Linear 的，不必额外付费。

主持

那你怎么去跟客户说：以前你们是按席位付费，现在我们要改这一套？

克里斯蒂娜

有帮助的一点是，按席位计费并没有消失，核心服务你还是要付的。而且我们并没有把以前免费的东西改成收费。【笑声】所以如果你去跟客户说「以前免费的现在要按用量收费」，那是完全不同的一件事。这些基本上是新功能。有时一个功能还在测试期，我们并不确切知道它会花多少成本、按用量该怎么收：你既可以跑一个非常贵的 Linear 智能体查询，也可以跑一个很便宜的，若单纯按每次查询一美元来收，在那种世界里就说不通。所以有时需要先让客户拿一个新产品去玩，才能判断成本是多少、哪种定价模型最好。

通常我们会把一个功能放在测试期，并说：这是一个仍在测试的人工智能功能，我们预计将来会收费，但现在是免费的，尽管用，看你能不能从中得到价值，并给我们反馈；等我们准备好收费时，会提前通知你。到目前为止，这套做法总体运转得相当好。我们也尽量对客户说得很清楚。不过有时测试期长达六个月，五个月后你才想起来：哦，我完全忘了这是免费测试，现在要收费了，我有点失望。这很难避免，除了在产品里做警示条、告诉你正在使用一个即将收费的免费功能，能做的也就这么多。我们只是想尽量对客户坦诚：这个功能的商业模式我们自己也还没完全想明白，但我们知道会收费，因为它的服务成本很高；希望你信任我们。但愿每次发生这种事，信任都是在往上积累，而不是往下掉。

另外，我们往往倾向一开始把价格定得更贵一些，再往下降，而不是先定得很便宜，然后说抱歉，其实没法按这个价格持续提供服务。用这种偏保守的方式，一旦能为客户降低成本、换来更多采用，我们就会降。

主持

你前面提到，刚进来时做了一份六到十二个月的走向市场计划。后来基本上是严格按那份计划执行，还是中途必须调整？到了 2025 年你们开始做新的智能体功能时，又是怎么改的？

克里斯蒂娜

我大概把该做的事情大部分都做了。虽然有段时间没回头看那份计划，但至少到现在，大体都做了。也许没有全部落在我原先设想的六到十二个月窗口里，但很多是组建团队、招人，以及开始更完整地思考产品发布：你不能只是把东西发出去、就赶着做下一个功能，必须持续地做教育和市场。这些已经变成团队新的动作和做事方式。销售几乎从没有团队，变成了公司里相当大的一块。所以这些事情最终都落地、都推出门了。你问题的后半句是什么？

主持

是 2025 年智能体功能出来的时候，你们不得不怎样改走向市场策略？

克里斯蒂娜

从走向市场的角度看，你有时会有一份长期路线图。当时上面很多是企业级功能，以及其他帮助我们进入市场的东西。而 2025 年，也正是我们宣布要去拿企业级客户的一年。接着我们看到这个领域正在发生的一切，就变成：必须做 MCP 服务器；必须做一套全新接口的智能体平台，让任何人都能把智能体做进 Linear；还必须跟 Codex、Cursor、GitHub Copilot 做合作，让这些智能体都进入 Linear。这些我们都做了，但没有一件是计划内的——2025 年初，我们并不知道自己会做其中任何一件。【笑声】

这并不意味着我们把这些加上原先计划的所有事情全都做完了。意思是，原先为特定规模工作区规划的、能帮我们扩向越来越大组织的那些企业级事项，有一批没有做成。很多东西没做完，但我当时的判断是：我们是想落在这些新事物后面，还是想跑到自己认为应该在的位置前面？我们选择往前冲。我也相信，只要这件事做得好，同样能赢来新的企业客户，只是赢法跟原先设想的不同。【笑声】那不会是去做子团队、多层工作流、跨多个团队协同的路线图——这些是大组织可能想要的东西。而是把那些让 Linear 跟智能体配合得非常好的能力做出来。因为我们做了，而竞品等了很久才做同样的事，我们走到了一个否则走不到的位置。很多本来不会把 Linear 放进候选名单的企业，因此把它放了进去。

主持

如果能回到你刚加入 Linear 的时候，以你现在知道的一切，你会告诉当时的自己什么？或者你希望当时就知道什么？

克里斯蒂娜

我大概会回去跟自己说：冷静一点，都会好的。我的意思是：我 2023 年加入 Linear 时，创业公司市场并不好。GPT 刚刚出来；2021、2022 年，在我们走出新冠疫情的阶段，很多公司融了非常大的轮次、当时也确实做得很好；到了 2023 年，就成了创业公司的大收缩——公司很难再融到钱，大量公司在大幅削减成本、合并支出。那种环境下要增长难得多，尤其我们 2023 年还聚焦在创业公司，以及一点点成长阶段的公司。

在很多意义上，你有时会在一个艰难的市场里起步。幸运的是，对其他所有人也一样难，【笑声】并不是只有我们不成比例地难受，但它确实影响了业务，你得想办法在缺少那种「本来会有的自然增长」的情况下仍然往前走。智能体化研发带来的变化也是一样：你得采取类似的态度，信任工程、产品和设计，去做出他们希望在这个世界上看到的产品，我们再围绕那一切去建商业模式。精确预测未来并不是我们的工作。

现在我们的产品路线图最多只做到大约六个月，因为谁知道事情会怎么变。这其实很有帮助：我们会为当下这个世界写一个故事，从市场的角度看，可以预期这个故事大概能支撑六个月，然后它大概就会演化、会变。我们不该害怕说：糟了，本来要上的那块广告牌是另一套信息，也许那套信息已经不对了。对，你就得动、就得改，都会好的。只是你不再拥有旧世界里那种时间：把一条信息、一套策略计划得妥妥帖帖再完美执行。所以这个新世界最终奖励的是速度，以及一种非常不同的运作方式。若让我回去，我想说的就是：离客户再近一点，把焦点放在这上面。

主持

你觉得这只是一个暂时的时刻，还是从此就会是这样：事情会一直以非常、非常快的速度继续变？

克里斯蒂娜

我觉得从此就会是这样。我在 2025 年夏天就说过这件事。按 Linear 以往的生意节奏，夏天会变慢，因为客户去度假，不买东西，也不会启动新的采购流程。我本来预期 2025 会像 2024 那样，结果完全不是，我们一直在全力推进。以前公司夏天不会发布产品、不会办大会、不会做这类事；现在则是：我就是要立刻上直播，提前一周通知就发布。以前还会在意不要周五发、不要周一发，现在谁在乎，周六发也没关系。我会说，所有这些规则都已失效，因为发布的东西太多、发生的事情太多。在人工智能领域出现一轮整合之前，我看不到这会很快改变。

主持

也总有人问，作为一门生意，你的护城河是什么？你觉得 Linear 刚起步时的护城河是什么，现在又是什么？

克里斯蒂娜

大概是出色的设计、出色的用户体验。现在我想，其实是出色的团队；此刻我还是会说，是出色的团队。【笑声】也许还有速度。不过这很难讲，因为我们如此在意品质，常常会为了达到某个品质门槛而推迟发布。所以我们不是绝对最快的，但也就意味着我们不是最糊弄的。【笑声】基本上是走在这条细线上。跟传统公司比，我们很快，但这都是一个光谱。对我们所竞争的对象而言，品质和速度之间有一个合适的权衡，每家公司都不同。我们更偏品质这一端，但仍然尽量快，并在合适的地方砍范围。

不过我觉得，商业里很多护城河其实已经在崩塌。现实是，你只需要一支对即将到来的变化有很好感知、很好脉搏的团队，并投资于你的团队和人，让他们有能力把事情想明白。因为昨天可能还是这个模型最好，明天就是另一个最好；两个月前你还没听说过的一家公司，现在已经在以 100 亿美元估值融资。一切都可以变，这意味着我们在很多意义上都该保持警惕：你曾经拥有的那门生意，未必就是未来仍会拥有的那门。但人们正在投资的，是一支团队、一种无论未来如何都仍然成立的做事方式。

主持

我一直觉得，拿护城河这个问题去问创业公司有点傻。你是创业公司，正因为你在挑战在位者。他们也许回头看有护城河，但你刚刚开始做一门生意时，是没有护城河的，这说不通。

主持

你前面也提到，你们是一步一步来的：先卖给创业公司，不能立刻去卖给超大型企业，当时只有一个销售。那为什么不干脆招 100 个销售，直接冲那些大客户？

克里斯蒂娜

那不会是 Linear 的哲学和做事方式。我们一直是「用更少的人做更多的事」。你去看大多数处在我们这个阶段、这个收入水平的公司，他们的编制几乎是我们的两倍，而我们能用更少的人做更多的事。这也意味着我们比别的公司更灵活，因为要转向时，你搬动的不是一艘巨轮。我不认为当时如果销售团队比整个公司还大，我们会做得好。【笑声】

一开始，这在我待在 Stripe 时也一样：很多科技公司对销售人员有一种相当负面的印象，觉得这是一群进来卖我们产品的「汽车销售」。我自己从不这么想，Linear 也不是这么想的。但那也许是大约 2010 年代科技圈对销售的印象。我的看法很不同，因为我相信，销售对于一门需要人际互动和说服的生意，有很大的推动力。对我们来说，小步、稳健地做，才在组织的不同部分建立起了所需的信任。

工程非常信任销售。当我们的销售团队在某个细分里遇到困难，会跟我们的产品经理一起开会，那种信任在于：这位销售真的理解客户的需求、他们在要求什么，必要时甚至会一起想解决方案。我觉得，靠短时间招进一大批人，是做不到这么好的。很多创业公司会走那条路，但他们大概更接近「招得快、开得也快」那种心态。【笑声】而我们招人要做工作试用，这向你传递的信号是：我们愿意花时间，真正判断一个人是否合适；希望把他们放进 Linear 所处理的问题范围里，看看他们在别处的出色经验，能不能很好地迁移到我们公司。这是哲学上的差别。每家公司做法不同，我会说，世界上很多优秀公司之所以用自己的方式做事，是有原因的。

主持

你们会从其他公司吸取灵感吗？

克里斯蒂娜

我在 Stripe 待了七年半，当然有些东西会从那里吸取。就拿招人来说：到了某个时点，Stripe 招商务人员的速度快过招工程师、产品和设计，创始人就说，这必须停下来。【笑声】那你们希望的比例是多少？于是你往后退一步：如果我们希望这家公司是工程和产品驱动的，大概至少应该有 40% 的人是工程、产品、设计、数据等等。我们就把它当成一条水位线，不能掉到这条线以下。这个数字其实是任意定的，就是 40%。【笑声】如果销售还想再加人，那就先帮我们把工程师招到，销售才能再招人。

是的，这是一个任意数字，但重要的是你得想清楚：希望自己的公司被怎样构建。有很多公司，比如优步，运营侧非常重，因为他们在移动的是人和实物。我们是完全不同的一类公司，是软件生意，不必有那么庞大的运营部分，因为我们不面对那些情境。所以要真正理解自己的生意、理解你想成为什么，再找出适合你的模型。Linear 并没有「必须 40%」这种硬性规则，但我会盯着这个数字。我做的第一件事之一，就是做了一张编制表，把每个人按职能归类、算出比例。我会看着它说：我们真的得把工程招聘这件事抓起来。招工程师永远会比招销售更难，那我们要做什么，才能让这件事对我们更容易一些？很多都回到哲学、回到你想成为什么。我待过一些公司，也想用同样的方式做事，同时比如说坚持不外包支持，或想以不同方式对待产品的不同部分。挑战就在这里。

有很多东西是我能从以往经验里带过来的，同时我也想用一些我还没在别人那里见过的新方式去做。

不从Stripe照搬的用人观、从运营到投资再回来，以及约170人仍保持扁平

主持

我接下来本来也想问这个。【笑声】有没有一些东西，是你明确不想从 Stripe 或 Notion 带过来的？也许举一个例子。

克里斯蒂娜

我觉得 Stripe 作为一家公司实在太成功了。在很多意义上，当你已经是一家市值 1400 亿到 1600 亿美元、还在上升的公司时，有时会相信自己总能招到比今天在位者更好的人。某个职能的负责人做得不错，你的第一反应却可能是：那是因为生意本身很好，不一定是因为这个人有多出色。就像有人说「我在谷歌，帮忙把收入提高了 200 亿美元」，可你到底做了什么？有时事情走得好，究竟是因为那个人，还是因为生意本身就在走好？而如果公司好到能吸引非常高质量的人才，你就能招到比那个人高两级的人，一年后再招到比那个人再高两级的人。你几乎总会去寻求比现任更好的人，因为你做得到。

对很多公司来说，能够说——我也跟我们的创始人说过——我们能找到更好的人，我们是一家人们愿意来、也感到兴奋的好公司，不必将就，这当然很好。但与此同时，你也必须真正看见自己已经拥有的那些出色的人。我觉得 Stripe 用了更长时间才走到这一点。Stripe 出现过不少回流：有人离开，也许是因为上升的节奏不像他们希望的那样，后来又回来，做得非常出色。我希望回头看自己在 Linear 的这段时间，能够说：该被提拔、该脱颖而出的人被提拔了、也真正起来了；除非公司需要进入一个不同的阶段、需要那个人当时还不具备的东西，否则我们不会在他们头上再压一层人——而不是仅仅因为我们不愿意让他们试着长到下一阶段。

做创业公司，对创始人也是一样：几乎没有哪个取得很大成功的创始人，是以前正好完整地做过一遍的。早期团队大概也会如此——他们是公司里的负责人，却从未把支持团队扩到 200 人或 500 人，但这并不意味着他们做不到，正如并不意味着一位创始人不能既在 50 人时出色、也在 1000 人时出色。我从根本上相信，人是可以成长、可以放大的，你应该随着时间奖励这一点。公司里不同部分有时未必总是相信这一点，不过从那以后已经变了不少。

如果还要再举一件，就是支持。要把支持做到那种程度，极其困难。而我们强调的品质，高于我运作过的绝大多数支持组织。我们在意这件事，也愿意为此付得更多，并相信这对客户是正确的做法。我很喜欢这一点。三年半以来，我从未因为有人在支持团队遭遇糟糕体验而接到过一次升级投诉。这就是一家我看见、也乐于置身其中的公司，而这并不是我工作过的每一家公司都能做到的。

主持

所以你先在 Stripe，然后去 Notion 待了一段，再成为投资人。是这样吗？为什么会转到做投资人？

克里斯蒂娜

是的。在 Notion 的时候，我喜欢那份工作，但真正喜欢的部分，几乎都是我并不是被招来做的那些事。我加入时大概 40 人左右，公司在扩张，却没有一个招聘人员，没有人力资源负责人，也没有人做增长。那我做了什么？我举手说：我来帮忙招人力资源负责人，帮忙招第一位招聘人员，找到第一位产品经理并把他们招进来。这些我都做了，等于把一些自己曾经承担的工作招人交了出去。然后又回到了自己「真正被招来做」的那份工作上：平台与合作负责人之类，【笑声】我发现自己对这份工作不再兴奋了。更有意思的，反而是那些并非我职责、却属于公司建设的事情。

当时我就想，我大概需要在另一家公司找一个新角色，却还不太清楚那个角色具体长什么样。于是觉得，风险投资也许是获得那种广度的好方法：跟许多不同类型、不同领域的公司待在一起。可对我来说，做投资人和真正走进一家公司做事，是完全不同的。给一家公司建议「你该多花时间跟客户在一起」「该想想这种商业模式」，和亲自去做，很不一样。而且我做的是早期，对，很早期。早期很多是产品市场契合之前就投进去；而我对你的市场可能一无所知，你也许是卖给采购负责人，或卖给建筑工人。要真正理解，你得身处其中。我反而觉得，当公司已经有了产品市场契合时，我更有帮助。回想自己加入过的每一家公司，几乎都是刚刚找到产品市场契合，然后我加入，再把生意搭建起来。

在产品市场契合之前，很多时候就是投对人、然后让开，提供支持和介绍。但我真正热爱的，其实是执行：待在一家公司里面，把事情做成。我这种人多少是以「会为把事情做成而去撞墙」被认识的，这在某些大组织里也许会惹人不快，但对创业公司非常管用。这对我是成立的。

主持

有没有一些事，是你发现「做过运营」让你成为了更好的投资人？反过来，做投资人又让你在现在 Linear 的角色上变得更好的，是什么？

克里斯蒂娜

我觉得自己是从一种有见识、也站得住的位置上在说话。很多投资人从未在创业公司工作过，这没什么错，也有非常出色的投资人从未在创业公司待过。这并不重要：你投对人，让他们去做自己的事，只要人投对了，这种策略就是成立的。但做风险投资也是销售：你在卖钱，【笑声】而其他每个投资人也都有钱可卖，某种意义上你们在卖同一件产品，你真正要卖的是你自己，是在金钱之外，把自己作为一件「产品」跟创始人差异化开来。对我这种在一些很出色的公司做过运营的人来说，走到创始人面前说「我能真正帮到你的生意」，会容易得多。【笑声】也许其他投资人也能。

主持

一个从未在公司里工作过的投资人，通常会怎么讲？是「我有很多介绍、已经投过很多很酷的公司」，大概就是他们的卖点吗？

克里斯蒂娜

很多时候是模式识别：我在这些出色公司的董事会待过，一次又一次看见过从零到一百的成功，也许能告诉你何时该做甲、何时该做乙，因为我是靠模式识别走到这里的。很多情况下，你合作的某些投资人有非常大的人脉册，认识很多出色公司里的出色的人，能把你介绍给在某些领域比他们更懂的人。所以常常会有投资人来找我：能不能帮帮这位正在考虑从零搭建销售团队的创始人？那我可以告诉你如何从一个人开始建。【笑声】因为他们认识我，这对创始人就是一个有用的接入点。所以对每个投资人来说，卖点都有所不同。

而我现在作为曾经的投资人再回到公司里做事，带走的是：当我坐在董事会上时，更能理解投资人在想什么。对，我曾经就是投资人，【笑声】所以对他们想看什么数据、在意哪些指标，更有感觉；如果我们在考虑新一轮融资，我对他们能提供什么帮助该有怎样的预期；如果我们需要更多客户，对他们的介绍又该有怎样的预期。我更清楚，自己作为公司这边，该从这位投资人或董事身上得到什么。这对公司在很多方面都有帮助。

主持

你是首席运营官，应该要经常跟投资人打交道。

克里斯蒂娜

是的。我们合作的一些投资人非常好，也帮了忙、推荐过人。但在很多情况下，不开口就没人喂你。你若不提出要求，他们是不会主动给你的。

主持

所以 Linear 除了创始人和你，就没有其他 C 级高管了？为什么？

克里斯蒂娜

这是个好问题。我们在 Stripe 很长一段时间也是这样运作的，所以我对此有偏好，不过对很多公司来说其实也是如此：你也许会在商务侧招进一位有类似头衔的高管。我会说，一开始，我的角色对一家很小的公司而言，几乎是各种不同职能的一个「收纳盒」，许多事情都会落到我这里。但我预期这会改变，不觉得会永远如此。如果我们在正确的位置上建起正确的团队和领导力，人们会配得上那个级别的头衔。

对我们现在而言，因为仍觉得自己很小——大概 170 人——在很多意义上我们仍希望保持相当扁平，而不是在人还不多的时候就加上很多层级。到目前为止，这对我们是有帮助的。但这并不意味着我们没有提拔人、没有给人更多责任、更多所有权和更大的范围。我们更倾向于用「负责人」这类头衔，去覆盖更宽的所有权范围。

主持

我这边就这些了。还有什么你想谈的吗？

克里斯蒂娜

没有了，这是一次很好的对话。我觉得我们走进了一家公司生意里很多不同的部分。谢谢，你的问题很好。

主持

也谢谢你。【音乐】
