一句话概述

潜空间（Latent Space）主持人肖恩·王（swyx）在人工智能工程师频道突破 100 万订阅之际，采访斯坦福兼职教授、摩纳哥（Monaco）人工智能负责人米哈伊尔·埃里克（Mihail Eric）。访谈顺着他第二次开设的 CS146S「现代软件开发者」十周大纲展开：从用约 200 行看懂编码套件、上下文工程和技能，到对智能体就绪的代码库、成为瓶颈的代码审查、安全供应链，再到后台智能体、软件工厂，以及学生如何在提高了的地板上让自己突出。

核心要点

  • 课程于 2024 年 11 月萌芽、2025 年秋首开，今年因自主编码智能体大爆发而刷新；不再是对软件开发生命周期各环节的广谱巡览，而是凝固上下文工程、架构设计等原则，并面向接近高级工程师而非谷歌 L3 的职场门槛
  • 开源贡献成为核心作业：学生已几乎无人纯手打代码；Factory、Cognition 等提供额外额度，学生向人工智能原生仓库提交并由维护者审查，以补上资深者与初级之间的鸿沟
  • 摩纳哥是旧金山 B 轮的一体式销售平台，服务种子轮到 A 轮创业公司；自建走向市场套件和「世界数据库」，并用一天约 6000 美元的飞机广告做破冰；工程上「买来学习、建来留下」，后台智能体平台叫 Monocoder，Slack 机器人叫 HAL，代码审查则收敛到 Devon
  • 生成速度使代码审查成为瓶颈，一天理论上可提 30 多个拉取请求；中间地带取决于就绪度和可验证性，部分改动可自动批准。安全上依赖与供应链是核心，数据、计费、认证与鉴权处不要氛围编程
  • 软件工厂仍有光谱，前沿公司自称完全由智能体驱动的贡献大约只有 30% 出头；人目前卡在意图和审查。基础设施会收敛成中间的「上帝盒子」（M×N 到 M+N），平台工程师被看作未来关键角色
  • 给学生的行动号召：经历并走出「智能体精神错乱」、做基准和评估、写严谨的工程博客；SWE-bench 最初像普林斯顿本科项目。Factory 甚至愿为超级用户提供上千智能体规模的额度实验

  1. 1开场：百万订阅、嘉宾介绍与斯坦福课程缘起查看原文 →

    潜空间（Latent Space）主持人肖恩·王（swyx / Shawn Wang）开场说，这期是在庆祝人工智能工程师（AI Engineer）YouTube 频道订阅数达到 100 万，并邀请尚未关注的人去订阅。嘉宾是斯坦福（Stanford）兼职教授、摩纳哥（Monaco）人工智能负责人米哈伊尔·埃里克（Mihail Eric，字幕常作 Mihil / Mihal Eric）：他在斯坦福讲授「现代软件开发者」课程（编号口播作 CS146S / CS146），正因覆盖人工智能原生开发实践而走红；他不但是老师，也是一线实践者。下周的人工智能编程峰会（AI Code Summit）将庆祝过去一年编程领域的极端进展，主持人预告的主题包括对抗「AI 稀泥」（slop）、系统一（system one）模型，以及提高野心、对几乎一切代码做大规模重写。进入访谈后，米哈伊尔说明这是第二次开课：课程约在 2024 年 11 月萌芽，当时编码智能体还是更早的版本，相关方法论只散落在博客里；他花了约九到十个月写成提案、过委员会，于 2025 年秋季首次开课（字幕曾作 fall 2020，按后文时间线应为 2025 年秋），反响很好，还登上《商业内幕》（Business Insider）。他向开过「设计机器学习系统」的好友黄佳（Chip Huyen）请教过课程设计。今年自主编码智能体起来的力度前所未见，因此整门课被刷新后再开。

  2. 2今年课程怎么变：从巡览到原则，以及学生焦虑与门槛查看原文 →

    主持人问，作为摩纳哥的实践者，他从去年到今年改了哪些原则。米哈伊尔说，去年还处在许多公司分别攻软件开发生命周期（SDLC）各环节的阶段——代码审查、规格设计、站点可靠性工程（SRE）都有对应的编码智能体——课程更像一次广谱巡览和「曝光」。今年一些原则正在凝固：非常仔细的上下文工程，以及用设计和架构处理超复杂任务。这门课不是给编程初学者的，也不能替代算法等传统计算机科学先修课，而更像面向即将进入职场者的实践者课程；摩纳哥和许多他咨询的公司都在面对超大规模代码库。学生焦虑仍然存在。他想论证的是：一名训练有素的人工智能原生素工程师可以成为几乎任何公司最有用的资产，但门槛高了很多——出校门第一份工作已不够只做谷歌职级里的 L3，而需要接近高级工程师的水平。基础软件工程、系统权衡仍然重要，实现细节可以更多托付给工具。主持人补了一句故意说得极端的观察：大多数学生「完了」（cooked），一部分会极其有价值；斯坦福学生大概会没事，美国其他地方则是开放问题。米哈伊尔解释客座讲座是刻意设计的：他自己是实践者，但不会声称握有全部答案，所以请站在更前沿的人（包括 Claude Code 相关的鲍里斯·切尔尼（Boris Cherny））来分享。主持人对比另一种「全是大名」的课，指出米哈伊尔同时还在产出「用约 200 行实现 Claude Code」这类可动手的教材。

  3. 3开源贡献作业与十周大纲：从套件内核到软件工厂查看原文 →

    主持人注意到开源贡献占了很大比重。米哈伊尔说这是他最自豪的安排之一：他花了夏天大部分时间和开源合作方沟通。去年有约九次偏教学的作业加一个开放式压轴项目，学生甚至可以「一枪打穿」；他周二的调查显示，斯坦福大二、大三学生中已没有人还纯手打代码。多数供应商有教育套餐（Claude、Cursor，可能还有 Cognition），他又争取了额外额度，避免学生被每月 20 美元订阅卡住，Factory、Cognition 等也在参与。目标是把学生放进复杂、大规模、人工智能原生的仓库里真正做贡献，让维护者审查代码、传递「什么是好软件」的心智模型，其中表现出色的人也可能被挖走。被问到学生如何用工具而不只是把作业丢进去一枪打穿时，他说仍保留一些偏概念的作业（技能、对智能体就绪的代码库、agents.md），但真正的试炼在开源和开放的期末项目。接着他广度优先地过了十周：第一周从零构建套件／克隆智能体（Claude Code 现已开源）；第二周规模化上下文工程、工具设计和模型上下文协议（MCP），他仍然支持 MCP，认为它已成为会继续存在的标准；第三周是技能与可重复流程；第四周是 agents.md、claude.md、钩子和子智能体等定制机制；第五周是他最喜欢的「对智能体就绪的代码库」（服务级边界、文档、可验证性）；第六周是正在成为新瓶颈的智能体代码审查；第七周是安全和新攻击面（今年从 Vercel 到大语言模型网关都有事故）；第八周是后台智能体，不只在集成开发环境里，也包括仓库触发器、持续集成／持续交付和站点可靠性工程风格机器人，并点名 Ramp Inspect、Spotify 自己的版本和 Stripe Minions；随后是团队级基础设施（大语言模型网关、MCP 门户）与角色演化；最终通向「工厂」——人还在哪里、意图和可验证系统等卡点，以及当 80% 到 90% 的代码由智能体驱动时会发生什么。主持人提醒：并非这一切都是已结算的科学，但这些都是人们在谈论、应该知道的开放问题。

  4. 4软件工厂光谱、Claude Code 爆发与用 200 行看懂套件查看原文 →

    即便「软件工厂」也有光谱：完全「黑暗」的工厂，和灯还开着一半的工厂。Warp、Factory 这些把工厂当服务来卖的前沿公司，自己也只声称大约 30% 出头的贡献是完全由智能体驱动的；有人在黑暗工厂上走得很远后出来说自己错了。鲍里斯最近发推承认自己经常错，主持人提醒不要把他的话当福音。米哈伊尔的原则是每天实验约 10 分钟。谈到代码审查周请来 Cognition：主持人曾和赛勒斯（Silas）一起做 Devon Review，觉得定性上相当好，虽有 Review Bench 但没人用；米哈伊尔确认摩纳哥在抽样多种工具后对不少用例收敛到了 Devon，并点名沃尔登（Walden）以及 Factory 很早推进的智能体就绪和就绪报告——Eno 在人工智能工程师大会上的演讲被认为超前，主持人还提到他们在 Cognition 讨论的同一周 Factory 就上线了整套产品。第一周重点是 Claude Code，但课程并不背书任何单一工具：去年开课时 Claude Code 还不流行，鲍里斯推特大约只有 4000 粉。主持人和鲍里斯、凯特（Cat）做播客时也曾低估它——当时大约才两个月大，一次查询花了 50 美分，还在测试中。鲍里斯去年 10 月讲座里有一页写着「为六个月后模型会到达的地方而构建」，后来的 Opus 被看作巨大解锁，也是课程大改的原因之一。米哈伊尔的博客结论是：凭斯坦福 CS106B 这种导论级算法理解，约 200 行就能写出承担编码智能体大部分工作的循环；课堂上先讲这 200 行，再用中间人代理（MITM proxy）拦截当时才两天大的 Opus 4.5，展示系统提示词、计划提示词和压缩提示词。来上课的还有其他院系博士后、医学和病理领域、以及其他工程专业的人，以及一些想「没有技术联合创始人也能做事」的商学院学生。Claude Code 的系统提示词曾长达约 2 万 token，也一度被砍掉 80%，并在变长与变短之间像跷跷板；早年它靠「更少工具做更多事」押注 SQL、Bash 这类瑞士军刀工具，而如何使用 git、如何布置任务等已从系统提示词转移到模型权重里，这正是「模型对套件」的投资权衡。

  5. 5上下文工程、REPIT 与写技能的艺术查看原文 →

    第二周的上下文工程里，米哈伊尔提出 REPIT 框架，功能上接近 Dex 的 RPI：先研究，再提案／规格，再实现，并用测试收束。他强调业界很少有人走出「原味提示词」；面对数百万行的陌生代码库，研究阶段本身有价值，研究之后还应给出几种替代方案，让人在回路里选择，再进入作为规格的计划。主持人补充了更别扭的一块：拆出子智能体时是否继承主线程全部上下文经常有分歧，分发工作已变成多智能体的上下文管理，审查智能体需要掌握一切，但给太多上下文又会让模型把一句旧评论当法律，于是在「愚蠢区」（Dex 的说法）里犯蠢。主持人还提到 Claude 托管智能体有会话分离、不继承的版本，并推荐人工智能工程师大会上反向工程 Claude Code 系统提示词增量、以及研究上下文窗口管理如何影响下游性能的论文。技能被看作从 MCP 这类单一工具调用走向可重复流程（如 skill.md）。他举例马特·波科克（Matt Pocock）的「Grill Me」和杰弗里·利茨（Jeffrey Litz）的 explain-diff：后者不仅可视化差异，末尾还有测验，逼你确认自己真的理解代码。主持人引用博客说，没有任何情况「把脑子关掉」是好主意；一行提示词换上万行代码看起来生产力很高，却可能把人甩出回路。学生现在大多已接触过 Claude Code，不过 Claude Code 和 Codex 都有桌面应用，Codex 更是主要作为应用使用。主持人强调应自己写技能而不是只消费网红技能，并介绍自己的「技能裁剪」技能——因为默认生成的技能往往又长又糟——以及技能在错误项目被意外触发的问题；尤金·严（Eugene Yan）会定期修剪不用的技能。他甚至怀疑 Anthropic 内部有人希望技能消亡，因为「每人守着一大堆 Markdown」并不像人们想象的通用人工智能。米哈伊尔则补充另一种更可能长久的定位：像 Devon 那样用技能编码组织级最佳实践（应用程序接口风格、服务级边界），而不只是避免重复写提示词。

  6. 6插曲：摩纳哥的飞机营销与一体式销售平台查看原文 →

    主持人搜索 Monaco AI skills 先找到的是那个国家。米哈伊尔笑称总有一天会在生成式引擎优化上赢过他们；他们买下 monaco.com 时被对方起诉，但这是件公开的事，他们赢了，域名留了下来。公司定期让飞机拖横幅飞行，点子来自营销方面的萨姆·布隆德（Sam Blonde，口播名），一天约 6000 美元，比广告牌便宜。广告往往只是「Monaco」加一个美元符号和数字（口播提到约 1.93 亿这类大数字），目的就是让人问「摩纳哥到底是什么」，从而在活动上获得破冰机会。萨姆的套路是：没有全部答案，就去试；从小处起步再做大。被要求正面回答公司是做什么的之后，米哈伊尔说摩纳哥是一家总部在旧金山的 B 轮公司，在做一体式销售平台：用原生智能体承担人类不喜欢做、智能体却能以更少差错完成的事，让销售把精力放在成交上。他们没有一上来就抢企业、硬拉人离开 Salesforce，而是在客户还只用表格追踪管道时介入，再像许多 Y Combinator 公司那样与早期客户一起从种子轮成长到 A 轮，现在开始更多向上市场走；他自称是最好的、或最强之一的面向创业公司的销售平台。作为人工智能负责人，他们自建了面向走向市场的智能体套件，驱动总可达市场（TAM）和理想客户画像（ICP）打分、管道演化，以及会前笔记和纪要等琐事，既有长程也有短程智能体。和许多垂直人工智能公司一样，他们先用前沿模型看可能性，再因成本（并提到 Harvey 近日被讨论的利润率波动）考虑在开源权重模型上后训练，主持人把这称为「智能体实验室剧本」。富集是核心能力：他们是 Parallel 的早期用户，也用 Exa，同时自建「世界数据库」；他认为自己世界级的地方是需求，例如销售副总裁刚换工作时（领英发生变化）更可能采购新平台。真正力量不只是一体式产品本身——他们为此潜行构建了一年多——也包括一支世界级走向市场团队：同一批人既在卖摩纳哥，也以派驻顾问的方式帮客户接入并搭建智能体工作流，其中有不少来自萨姆在 Brex 等地的前同事。

  7. 7摩纳哥内部工程：Monocoder、HAL，以及「买来学习、建来留下」查看原文 →

    桥接回摩纳哥内部的现代软件开发，米哈伊尔说他们从第一天就投入编码智能体，并越来越多把伤疤和心得写在博客上。许多东西最终选择自建：后台智能体平台是他们自己版本的 Ramp Inspect，叫做 Monocoder，构建在 Coder（coder.com）上，用于隔离开发环境、扩展多智能体和跑长程任务，向约翰·特雷西（John Tracy）致敬。他们还做了 Slack 机器人 HAL（向尤娜（Yuna）致敬），它同时承担排障、提交拉取请求、以及帮销售搞懂产品的角色，因此对销售和开发者需要不同「人格」。原则是「买是为了学习，建是为了留下」：外面没有足够成熟的产品时才自建。代码审查是反例——大约一年多前他们评估过 CodeRabbit、后来被收购前的 Graphite、当时还是 Y Combinator 公司的 Ellipsis 等，都还没跨过「立刻有用」的门槛；第一次评估甚至做了基于拉取请求的统计分析。后来有人（可能就在赛勒斯来课上讲座前后）让他们再试 Devon，这一次几乎纯凭体感就觉得好用，团队开始有机要求被加进去，痛点也还没痛到要撕掉重写，因此他们仍使用 Cognition 的 Devon。主持人说自己只是 Devon 顾问、已不深参与，因而特别看重这种没有私心的外部评价。回到课程，第四周更多是定制智能体的概念基础，第五周才真正应用到真实代码库；米哈伊尔强调 Factory 的就绪报告：对多智能体和并行化的兴奋之前，必须先有可验证、结构良好、能被智能体理解的代码库，这是通向后台智能体和软件工厂的第一块积木。

  8. 8智能体就绪、用日志和分析闭环，以及企业级人工智能运维查看原文 →

    主持人指出课表上不够显眼的一块：站点可靠性工程要真正闭环，智能体应能读构建日志，最好还能读线上生产分析。米哈伊尔同意，并说会把它织进后台智能体周和软件工厂周；基于触发器或事件启动任务，现在是软件工厂里两三个主要入口之一。主持人挖苦说，所谓事件驱动往往只是定时任务先把事件捞出来，底层全是 cron 或网络钩子。被问到哪些人工智能运维公司留下印象时，米哈伊尔点名 Resolve，以及有 Greylock 支持、做广义后台智能体的 Night Shift。他认为这类产品在企业最有价值：海量服务依赖、成吨 Kubernetes 与 Helm 文件散落各处，Resolve 会卖给福特、沃尔玛去理清服务级依赖；小规模则往往还可以自建。主持人补充那种规模是数万个仓库、仓库比开发者还多，写代码的人多半已经不在，值班的人面对过时运行手册——对「一个人一个仓库」的大学黑客完全没有这种体感。Resolve 去年还为课程做了沙箱作业：多个服务里埋了缺陷，学生要用他们的智能体扮演值班人员去探测。米哈伊尔提醒，对企业而言，拖住他们的常常不是「再多一个智能体」，而是更底层的开发运维和持续集成／持续交付，例如合并队列堵塞、应用拉起太慢；再扔一个运维机器人解决不了系统性的问题。这也自然过渡到合并队列和代码审查。

  9. 9代码审查成为瓶颈：自动批准、规格真相源与程序数据库查看原文 →

    米哈伊尔把第六周比作写给现代智能体代码审查的情书。最大变化是生成速度高到理论上一天能提出 30 多个拉取请求，审查突然变成瓶颈：若人仍按传统方式做门禁，自己就成了卡点，规模化生成就失去意义；若完全放飞又没有信任。中间地带取决于智能体就绪和可验证性是否设计到位——有一类问题可以在相当比例的时间里自动批准，其余的仍要决定是逐行看还是用别的方式看。主持人提到潜空间客座作者、阿维亚托（Aviator）的安基特（Ankit）写过「杀死拉取请求审查」，并设了几道门。米哈伊尔读过并大体认同，同时指出卡点其实有两个：审查，以及顶上的意图。统计上更明显的是合并在增加，审查并未同比增加；Amplitude、Cloudflare、Augment 都写过设计人工智能代码审查系统的好文章。关于规格是否始终更新：摩纳哥把拉取请求描述写成几乎覆盖实现的压缩规格，甚至带文件和行的指针，并认为只要它代表代码库此刻最更新的东西就够了。主持人反驳说，功能／代码库级规格才是所有拉取请求的总和，模型和人都很难维护「五周前做过的另一件事正在被逆转」这种隐性意图。米哈伊尔提到会计公司 Basis 用 git 同时追踪「应当如何」的规格和代码的「规范状态」；主持人则构想一种取代 git 的「程序数据库」，捕获轨迹、规格和技能，并解决 git 只聚焦代码、又到处加互斥锁因而难以高并发的问题，同时点名 GitButler 的斯科特（Scott）。他认为理想任务表示的赢家也许是 Linear，因为它已成为任务的真相源，并明显在变成编码智能体公司；米哈伊尔进一步猜测，许多收集用户或产品洞察的企业软件公司（Amplitude，甚至 Decagon 或 Sierra）都可以把闭环做成某种编码智能体。

  10. 10安全：供应链、开源阳光，以及数据、计费与鉴权不能氛围编程查看原文 →

    安全被放在第七周而不是第一周。主持人引用亚马逊「零号工作就是安全」（安迪·杰西常说，他在贝索斯到杰西过渡期待过亚马逊）。米哈伊尔说这是去年就有的主题，艾萨克（Isaac）也来讲过；Semgrep 在智能体时代之前就有开源防御工具，并增强进了这个空间。核心洞察是依赖追踪和供应链：不要随手 npm install。主持人把极限推成「最安全的代码库也许没有依赖」，米哈伊尔承认代码商品化后全部自建理论上最安全，但也「说起来容易」。主持人警告这很危险：开源的意义是「阳光是最好的消毒剂」，10 万用户比你自己的用户更快发现缺陷。米哈伊尔则相信大多数开源仓库未来都会变成由智能体运行的软件工厂（Warp 已把开源终端当工厂来跑），人类审查会变少，这究竟让安全更好还是更差仍不清楚。主持人转述 Vercel 的马耳他（Malta）把高依赖的 C／C++ 软件迁到 Rust 的主张，以及模型实验室用 Daybreak、Glasswing 等放慢节奏、打好补丁再加速的论点，并质疑「模型会修好所有安全问题」尚未被证明——它们可能引入不同的新缺陷；即便交给模型做安全并推迟发布，给三个月测试也挡不住别人用六个月去利用。他还提到若把「受祝福」的组织名单和网络模型交给优先对象，等于增加攻击面。风险投资视角下，过去五年真正成了的安全公司据说主要是 Wiz 和 Socket，最好卖点永远是刚发生的高调事故。更关键的问题往往不是模型平均缺陷更多，而是人对正在被写下的东西意识更少，因此安全检查应进入代码审查。主持人的直觉是：数据存储、计费以及认证（authn）与鉴权（authz）这些部分不要用氛围编程，其余可以放开；若不懂这些词或没看过亚马逊云科技的身份与访问管理（IAM），就无法在提示词里调用它们。DNS 事故更多属于正常运行时间，安全应优先问有没有亏钱、有没有泄露客户信息。

  11. 11后台智能体、MCP 门户与「上帝盒子」：捆绑、拆绑和平台工程师查看原文 →

    客座讲师和周次并不严格对应：第九周因档期请了埃拉德（Elad），米哈伊尔自己那周不讲课，相关话题会在第十周回来；第八周是 Cloudflare 负责基础设施与开发者体验的拉杰什（Rajesh）。后台智能体要讲的是异步智能体的多种用法，并再次以 Stripe Minions、Spotify 的 Muse（口播还提到 Tag Instinct）和 Ramp Inspect 为例。主持人提到面向消费者、但据说底层是 Cursor 的 Grockbot（口播亦作 Grockpot）：他自己只用它订过 OpenTable，而其卖点是普通人也能用，懂的人则能碰到下面的代码能力。他进一步说，自己的搜索引擎优化和生成式引擎优化都在带代码库的 Codex 里跑；只要持续做步骤多、数据多的事，就需要代码库，许多表面上非技术的用例引擎盖下已是编码智能体。谈到团队基础设施，主持人对 MCP 本身看好，对「MCP 门户」作为生意最不看好，甚至想过创业后来失去兴趣。米哈伊尔则认为门户只有在必须用单一入口做治理、审计和成本优化的规模上才有意思，类似 OpenRouter 那样的连接点。主持人修正说它会折进大语言模型网关，再和鉴权、权限、计费一起收敛成中间那个「上帝盒子」；把门户和网关拆开，等于没看清它们是同一层问题，就像有人把数据库查询里的过滤和排序拆成不同层。他的呛人表述是 M×N 到 M+N：基础设施工作不是在造上帝盒子，就是在拆掉别人的上帝盒子，直到宇宙热寂——也就是软件的捆绑与拆绑。OpenRouter 只做模型路由且很成功，不去做 Arise 那种运维和可观测性，是他喜欢被打脸的单点反例。米哈伊尔提醒，企业里这些东西虽同属平台，却由不同团队拥有，收成单一端点往往是政治问题。主持人用康威定律说：你交付的是组织架构图，你买的也是；如果工具「为所有人」就是「为没有人」，所以潜空间和人工智能工程师大会有意识地只做给真正把人工智能当日常的那一类工程师。米哈伊尔点名未来越来越重要的角色是平台工程师；主持人说若他没做现在这些事就会去做平台——因为平台拥有云、开发者体验和安全运维，也就是能让公司沉船的那些事。

  12. 12软件工厂里的人、学生如何突出，以及临别行动号召查看原文 →

    软件工厂被说成「建造机器的机器」。米哈伊尔认为人目前仍卡在意图（定义规格）和审查两处，而审查会比意图更早被松开。Warp 作为开源合作方，将提供一个正在运行的工厂版本，让学生在工厂里贡献并维持它。整座工厂很难被一家公司一次性卖给福特这类客户，更可能先做编码智能体，再做后台智能体和部分运维，再落地扩张。主持人提到 OpenAI 一篇约在 2 月、题为「套件工程」的博客（他们请过瑞安（Ryan）上节目）：花五个月做出零行手写代码的内部工具，过程先慢后快，并保留同行审查。角色问题上，两人曾与杰里（Jerry）、Dex 讨论：抽象层会上升，但仍需要有人理解各组成部分以设定方向和指标，也就是某种「智能体经理」。主持人刚问过 Anthropic 的产品负责人和平台工程负责人工作何时合并，对方说「还没有」，因此不必觉得迫在眉睫。对他更有共鸣的是递归：从写提示词，到写会写提示词的提示词；应从下往上建到工厂，而不是现在就从上往下——那会制造大量稀泥。他问两年后若拉取请求合并率变得荒唐，工程师的「主业」是什么；若角色演变成产品工程师，客户满意度可能比代码指标更接近答案。米哈伊尔建议学生思考整体系统，并把 Y Combinator 的「征集创业想法」当作期末项目种子。去年有电气工程学生把带 C 语言内存地址的手册解析成可解释、可视化的代码；有设计师给笔记本拍照生成完整 Vercel 应用，后来进入 Vercel，现在和开源合作方 Eve 有关——这被说成「元套件」。硅谷以外仍有大量公司停在 ChatGPT 或刚发下 Cursor 许可。主持人提到史蒂夫·耶吉（Steve Yegge）关于「精神错乱层级」和 Gas Town 的公开旅程：在那里建出的唯一有用之物就是 Gas Town 本身；方向上应从集成开发环境走向重度用户、从单智能体走向多智能体并尝试自建编排器，但必须以交付真实产品为约束。作为雇主，他不想招还没经历过并走出这种精神错乱的人，因为薪水加 token 的学费极贵。鲍里斯则给出团队采纳的五个层级：门控、辅助、并行、有监督的自主、人工智能原生；Anthropic 自称仍在第 3 阶段、想进入第 4 阶段，并把按需写套件称为动态工作流，摩纳哥也做了走向市场版本。临别时米哈伊尔说这门课酝酿了约九个月，现在第一周结束，明年还会再开，开源方可联系参与。主持人强调额度：Factory 甚至愿意为想「彻底放开」的学生做扩展到一千个以上智能体的实验；Cursor 的威尔逊（Wilson）那种「我要去写一个浏览器」的野心才值钱。去年教 k-shot 提示的水平今年已算不合格。他送学生一个「第十一周」：做基准和评估，写出带严谨性的工程博客——SWE-bench 最初就像普林斯顿的本科项目——这既能敲开前沿实验室的门，也可能做成生意。

swyx

米哈伊尔

我们从编码智能体的内部机制开始。你会教大家怎样写出自己的 Claude Code 克隆——它现在开源了，这非常有帮助。第一周全是套件（harness）的内部：从零构建一个克隆智能体。第二周则是：假定这些已经存在，我们如何在规模上思考上下文工程，超越普通的提示词；同时会谈到工具设计和模型上下文协议（MCP）。有一阵子 MCP 被很多人骂，我仍然挺 MCP，也天天见到它。到了这个时点，它已经是存在的标准，我相信还会继续存在。所以有效的工具设计是第二周。第三周更多关于「技能」：怎样从单一用途的工具，扩展成可重复的流程，技能会导向智能体的自动化。第四周是定制智能体的基础：像 agents.md、claude.md 这样的配置文件、钩子（hooks）、子智能体（sub-agent）——现代套件里有很多机制，用途不同，我想让学生接触到。

「对智能体就绪的代码库」大概是我最喜欢的主题之一，对即将进入工业界、思考大规模代码的人尤其相关：什么样的仓库能被智能体有效地吞进去、消费掉？既要思考服务级边界的设计权衡，也要思考文档和可验证性。这是第五周。第六周是智能体代码审查。从第五周的就绪代码库延伸过来：代码审查正在变成瓶颈。除非有些硕士生已经在业界待过，很多学生没见过这个；但今天大量使用编码智能体的人，都体会到审查成了新瓶颈。我们怎样把这个瓶颈松开一点？有哪些机制，可验证性如何延伸进审查流程。第七周是安全。去年课里就有，今年我还要强化：任何大量采取行动的自主系统，今年我们看到很多东西被攻破，其中不乏从 Vercel 到大语言模型网关这类核心软件。我想花些时间谈安全里有哪些新的攻击面，以及如何缓解。

第八周是后台智能体（background agent）：怎样在许多不同的产品和服务区域里跑智能体，不只是传统的集成开发环境（IDE），还包括基于代码库和仓库触发器、在持续集成／持续交付（CI/CD）期间、基于事件触发的东西，比如站点可靠性工程风格的机器人。怎样构建这样一套系统？过去这一年，很多公司开始发布文章：Ramp 的 Inspect、Spotify 有自己的版本、Stripe 的 Minions，都有很精彩的内部实践写稿。我想让大家接触这些。然后是现代团队里的团队级基础设施：大语言模型网关、规模化的 MCP 门户（MCP portal），以及如何思考不断演化的角色。说「每个人都是构建者」有点太干、不够细致，我想再往下走：什么东西正在被吞掉，哪些角色在演化或是以前不存在的新角色，学生该思考哪些比以前更站得住的技能组合。这更多是团队动态层面的考量。

这一切都通向「工厂」（factory），这是很多人现在最关心的：我们开始建造工厂之后，人还在哪里？有哪些新的卡点是故意留给人参与的——比如意图、比如把可验证系统搭起来？当也许 80%、90% 的代码完全由智能体驱动时，我们填充进那个图景的是什么？大概就是扎实的十周。

米哈伊尔

swyx

这三层很好：学生作为消费者、基线的循环智能体、以及真实的那一个。我喜欢你博客文章还配了视频讲解。你有没有看到两极：有些人是重度用户、消耗量很大，有些人如果你已经懂智能体就会觉得这些非常直白？课堂里你怎样平衡，是不是对准平均值？

上下文工程、REPIT 与写技能的艺术

↑ 返回总结
swyx

第二周你要讲上下文工程。我还没见过你写的 REPIT，但规格驱动开发已经有很多版本。面对更广的听众，这里有什么是他们应该知道的？这几乎是把整门课压成一小时版。

米哈伊尔

对，有点像预告片：想听更多，就明年或下一个秋天来选课。不过到你下次再教的时候，它可能又变了。我想强调的核心是——我面试别人时也经常看到——业界里很少有人真正走出「原味提示词」：表格一填，「帮我做那件事」。模型变强之后，这能带你走一段；但任何从谷歌这类拥有海量代码库的地方出来的人都会告诉你，现实是你必须更用心地思考如何把东西吃进上下文。

我这里说的 REPIT 框架，功能上接近 Dex 的 RPI 一类做法：先研究（research），再有一份提案／规格，然后实现，再用测试之类的东西收束。我想强化的是：尤其当你进入不熟悉的代码库、想把智能体需要理解的、关于超大代码库的信息注入上下文时，研究阶段本身就有价值。在我提出的这个框架里，研究之后还要给出几种替代解法的提案，并邀请人在回路里做决策者，选择走哪一条，然后再进入作为规格的计划。一句话：有办法把这件事扩展到数百万行的代码库，而不只是一句原味提示词。如果你要去这类大代码库里工作，就该用更精细一些的流程。

swyx

关于上下文工程我能补充的、也是我现在想得最别扭的一点，是拆出子智能体的时候：子智能体可以继承主线程的全部上下文，也可以不继承。这一点经常有分歧。有时你想把子智能体做的事压缩后再放回主线程，过程非常黑客、我对自己正在做的事并不满意，也给不出答案。我只知道：当你要往外分发工作时，已经不再是「一份大规格、做一遍 RPI 或 REPIT、一个智能体」了，而是分发出去，并确保它们都有正确的上下文和正确的指引。如果你还有一个审查智能体去审其他所有工作，那个家伙得掌握一切。你总会经历这种扩张—收缩：天哪他们上下文不够，我再给一点；然后他们又会过度拟合你很久以前随口说的一句评论，把它当法律，于是犯下很蠢的错。我不知道该怎么命名，大概是面向上下文的多智能体管理。

米哈伊尔

完全正确。这可能是其中最「艺术大于科学」的部分：探索时的分发、子任务的分发，然后是合并、压缩，无论你怎么叫它。要用心考虑何时刷新上下文，何时东西开始过于膨胀。Dex 有个「愚蠢区」（dumb zone）的概念，就是提醒你对这个区域更敏感。他很擅长发明这类说法，也配小图。

swyx

图很有用。我为想深入的人补一点线索：最好能看到各家在子智能体是否继承上下文上的偏好。Claude 托管的智能体有一个版本是会话分离、不继承。这在推理模型出现之前、智能体跑不久、上下文窗口更短的时候，曾是热门话题。LangChain（字幕作 Lingchain）以前写过很多这方面的博客。好的上下文工程，这些学生上完你的课都该知道，你自己应该知道得更清楚。这也是一块有趣的研究空间。人工智能工程师大会上有一篇研究论文，看了 Claude Code 系统提示词的增量变化，画出一堆性能变化，试图反向工程。还有一篇看上下文窗口管理如何影响下游性能。它们未必是最好的论文，但很易读，也带出好博客，想做的人可以很容易伸手去戳。

米哈伊尔

技能（agent skills）可以看作从单一的、所谓函数式工具调用——比如 MCP、与第三方外部服务交互——再往前走一步，变成流程：你如何把一套反复做的动作形式化，写成 skill.md 之类的东西。我想让大家做一些把流程编码下来的练习。我也会放进一些我觉得好用的有趣技能：马特·波科克（Matt Pocock，字幕作 Matt Pox）的「Grill Me」（字幕作 grill knee）就很好；从教育角度看，我还喜欢杰弗里·利茨（Jeffrey Litz）的 explain-diff，一旦讲到代码审查就特别有意思——你必须理解代码。

你跑这个技能，最后不仅会得到某种可视化，可以扫一眼看清改动的核心，我真正喜欢的是末尾几乎像测验一样的部分，逼你确认自己是否真的理解发生了什么。这种互动来回很舒服。

swyx

这个领域有几篇我很爱提起的博客。最近有一篇大意是：没有任何一种情况「把脑子关掉」是好主意。这些技能其实是逼你把脑子打开。而大家用编码智能体时，却往往想把脑子关掉：给我做个应用，读懂我的心思，什么都别让我讲就全部做对。很多这类技能的类型其实是：不，请多问我一些问题。我一行提示词就能得到上万行代码和完整结构，看起来生产力爆棚；但你更应该清楚自己在做什么。把代码写出来已经比从前容易得多，理解却没有任何借口可以省掉。否则你会被甩出回路。

米哈伊尔

网络类技能，基本上就是和网络本身互动的技能，包括计算机使用（computer use），主要是从网上拉取信息。我这里更多是对一些我觉得有意思的东西做一次巡览或演示，不一定是完整的最佳实践对照。有个站点——我记得可能和浏览器或 Browserbase 有关——展示过一些有趣的能力。命令行也是有意思的一块。

swyx

学生是不是很多人第一次进终端、进命令行，还是现在已经是常态？

米哈伊尔

我不这么认为。去年可能还有人记得手指敲键盘的日子；现在大多数学生至少已经和 Claude Code 打过交道。

swyx

我好奇现在有多少人只用应用：Claude Code 也有桌面应用，Codex 也有，而且 Codex 现在主要是应用，你并不在命令行、不在终端里。这会让很多普通人却步。只是随手一提。

米哈伊尔

技能还有一种是技能包，彼此交叉引用，有点像插件。此外还有「写技能的艺术」，这也是我为人工智能工程师大会关注过的。很多讨论都在讲如何消费技能，网红会说这个技能能解决你所有问题；不，你应该自己写技能。而且你若天真地去写，通常会写得很差，写技能本身需要一点「技能」。

swyx

我有一个公开的技能仓库。我经历过一段「万物皆技能」的精神错乱期。怎么写出好技能？我有一个专门用来砍技能的技能。Claude Code 和 Codex 都有「创建技能」的技能，我又写了一个「技能裁剪器」，专门记录那些默认生成技能的各种糟糕之处，所以每次技能被创建之后你都该跑一遍它来砍短。讨厌的是，有时稀泥里也有好东西，你得把它们削出来。而那种稀泥仍然是智能体的语言，所以稀泥本身也意味点什么。先做起来很容易：调用几次，凭感觉检查，再把这些偏好蒸馏成「我喜欢这样、不喜欢那样」的技能，它会随时间调整，然后被自动化。最糟的是技能在你没预料到的时候被触发：你当年为修一件事写下它，触发条件写着「每当某某发生就叫我」，你换了另一个项目它又触发了，你完全摸不着头脑。有些人比如尤金·严（Eugene Yan，字幕作 Eugene Yen）对技能数量非常挑剔，不常用的就修剪，每隔几周清理一次。

如果你深陷技能世界，这会是个大问题。我甚至怀疑，Anthropic 那边有些非常聪明的人其实希望技能消亡——这不是公开流行的说法，他们不会公开这么讲——只是这一切感觉很稀、很糊。这也不像人们以为的通用人工智能该有的样子：每个人守着一大堆 Markdown 文件。

某种意义上这是一个园艺问题。很多人其实从不看那些 Markdown 文件。用户体验可以是：用聊天说出你想要的，生成技能，用它，看输出。在某种程度上不必把自己搞得太复杂，重复做的事就说「看看我们最近五次怎么做的，给我做个技能」，用聊天迭代，也有好的一面。

米哈伊尔

还有另一种看法：技能不只是智能体每次做代码审查时要跑的流程。以 Devon 为例，我们把技能编码成最佳实践的一种表达，再暴露给智能体、给代码审查系统，让它按我们喜欢的方式定义应用程序接口、按我们定义的方式落实服务级边界。这是在表达组织级知识，而不只是「免得你每次重写提示词」的随意流程。我喜欢这种定位，觉得这个用途可能比那些随机流程活得更久。

米哈伊尔

分几个地方。有一份规格存在于 Linear 的议题里，也有一份规格存在于拉取请求描述的上下文里。你可以把拉取请求描述写成几乎覆盖全部实现、但更压缩的说明。只要它是代表代码库此刻最更新的东西，我觉得就足够了。所以我们很认真对待拉取请求描述：不只是一段话，而实际上就是这份拉取请求里发生了什么的规格，甚至有到文件、到行的指针，指出改了哪里。你既能看到高层面发生了什么，也能看到文件的构造、你碰到的服务级边界。我们在这上面投入了不少。

米哈伊尔

这是一个很有意思的洞察，也是推到极限的说法。说起来容易做起来难；但如果你相信代码正在商品化、又便宜又容易，为什么不全部自建？那样最安全，因为你看见一切、控制一切，而不是去依赖 Axios 之类的东西。有多少人会真的这么做另说，但那确实是最安全的。

这个陈述很危险，因为那样你只是在犯自己的错，而不是依赖别人去发现错误。开源的全部意义，有点像「阳光是最好的消毒剂」。你自己的定制软件依赖会非常慢才被发现，因为你只有自己的用户，他们也不会向你报告；而如果这东西在全世界有 10 万用户，就会有人发现点什么，然后你可以更放心地依赖它。我是想当一个理性的声音：两边都不能绝对化。我刚才几乎是把你带进了「一切都用供应商」的话术里，那里面有坑。

米哈伊尔

米哈伊尔

swyx

米哈伊尔

完全同意。某种程度上我甚至把这延伸到某些云平台的事情上。我忘了是哪家公司出过一次大事故，好像只是域名系统（DNS）问题就导致了宕机。

swyx

你得再缩小范围，突出的 DNS 事故有过很多。永远是 DNS。不过 DNS 更多是可靠性和正常运行时间。安全我会问：你有没有亏钱？有没有泄露客户信息？那些应该排在更前面。DNS 主要是因为正常运行时间和服务级别协议。

这类「进阶」谈话里，大约一年前史蒂夫·耶吉（Steve Yegge，字幕作 Steve Yaggi）谈「精神错乱的层级」仍然非常有影响力。他现在已经走到第 10 级，放弃了，搬去农场——我是在开玩笑。他建了 Gas Town，我记得后来又搬到 Gas City，再把城市烧掉，说我要去做自己的游戏，不再要 Gas Town。今年早些时候在工程师大会上我和他聊过：在 Gas Town 建出来唯一有用的东西就是 Gas Town 本身，那是一次可怕的失败。人们应当意识到精神错乱是真的：如果你不把自己约束在交付真实产品上，你只是在和语言模型瞎拧。

米哈伊尔

作为雇主，我公司里今天就有这个问题：我不想雇用任何还没经历过精神错乱并走出来的人。因为我正在付钱让某个人去经历精神错乱，薪水很贵，token 也很贵，我什么都没得到，而我的反馈也穿不透。所以我几乎想鼓励你的学生去经历精神错乱，再走出来，问自己：我刚才是怎么了？史蒂夫刚刚公开走完了大约两年的这种旅程。学生这边的版本也许是：你以为自己很有生产力，其实没有——你在 Notion 里画流程图，做各种个人操作系统优化，然后发现一切都没变。那就走过去，再走出来。
