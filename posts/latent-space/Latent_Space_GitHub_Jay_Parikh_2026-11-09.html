一句话概述

潜空间（Latent Space）主持人肖恩·王（swyx / Shawn Wang）在 GitHub Universe 主题演讲结束后，采访微软（Microsoft）CoreAI 执行副总裁杰伊·帕里克（Jay Parikh）。访谈覆盖 GitHub 的极端规模（2.25 亿开发者、连续第二年每秒新增一位）、智能体正在改写平台构成（约 40% 的拉取请求由智能体创建、六个月增长六倍）、Copilot 套件与 Fusion 模型路由、跨界面同一会话、安全扫描与开源供应链，以及 2027 年迁往 Azure（Azure）和 token 治理的展望。

核心要点

  • GitHub 现有 2.25 亿开发者，覆盖世界上每个国家，连续第二年每一秒新增一位；Octoverse 报告（口播作 Octiverse）还有 179 亿次代码推送、343 亿次提交、13 亿个拉取请求；开源贡献比去年增长两倍半
  • 主持人开场引用：约 40% 的拉取请求由智能体创建，智能体总量六个月增长六倍；人类采用仍在增长，他们还一边迁往 Azure
  • 面对彼得·施泰因贝格尔（Peter Steinberger）等把平台用到极限的用户，杰伊认为拉取请求等概念可以做成可配置的，但面向 2.25 亿开发者必须提供可组装的原语；他自己有些仓库也不走拉取请求
  • Copilot 套件（harness）以多模型为原则，SDK 可被用来做其他应用；Fusion 负责在众多价格—性能不同的模型之间做路由，卸下工程师的认知负担
  • 手机、桌面、VS Code 与 GitHub.com 共用同一套套件，仓库、issue、拉取请求、安全发现、记忆和偏好在一处复利；在不同供应商的工具之间切换则无法叠加智能
  • 安全上有 Code Review Max、密钥在进入仓库前拦截（达米安演示）、GitHub 高级安全加 AI 扫描，以及与微软安全团队协作处理 npm 等暴露面；杰伊反对把 2000 个依赖砍到 20 个再自己维护剩下的 1980 个，主张把开源做安全而不是走进围墙花园。明年目标包括完成迁往 Azure；财富 500 强要治理和限额；例：一周花 1000 美元 token，若能对应 2.5 万美元收入就说得通

  1. 1开场：GitHub 同时服务人类与智能体，介绍杰伊与 AI Engineer CODE查看原文 →

    肖恩·王（swyx / Shawn Wang）开场说，GitHub 处于所有开发的核心，也越来越成为智能体（agent）与人类协作的方式。有人常提起它的停机与可靠性：它被说成是今年第一家在可靠性上达到「几个 9」的服务（字幕作 reach 09s in reliability，或指 nines，具体 SLA 未说明，不作臆测）；但外界不太知道，它正以极大的规模自我演进，以同时适应人类和智能体的需求。今天的嘉宾是微软（Microsoft）CoreAI 执行副总裁（EVP）杰伊·帕里克（Jay Parikh，字幕常作 Jay Parrick），他认为杰伊实际上也在领导包括 GitHub 在内的许多核心 AI 服务。他们此前采访过 GitHub 首席运营官（COO）凯尔·戴格尔（Kyle Daigle，字幕作 Kyle Dagel）；在 GitHub Universe 上，GitHub 发布了大量关于基础设施层、模型层和应用层的更新，其中包括大约五六年前推出的原版编程助手 GitHub Copilot。一组数字令人震惊：GitHub 上大约 40% 的拉取请求（pull request）由智能体创建，智能体总量在 6 个月内增长了 6 倍；与此同时人类采用仍在增长，开发者数已达 2.25 亿——他记得 8000 万开发者曾是一件大事——并且基本上每年每一秒都在新增一位开发者；他们还一边做这些，一边迁往 Azure（Azure）。杰伊的履历很适合扛这件事：他曾任 Facebook 工程负责人、Lacework（字幕作 Lace Work）首席执行官，以及 Ning 和阿卡迈（Akamai，字幕作 Akami）的工程副总裁，像是基础设施、安全与社交媒体的「复仇者联盟」；别忘了 GitHub 本身就是开发者的社交网络。道路并不平坦，谁也不能对停机扔石头；有人在寻找 GitHub 的替代品，但 GitHub 始终是 GitHub，理解并帮助这个大家协作、发布开源并发现安全问题的核心平台演化，符合所有人的利益。他们正在筹备本年最后一场、也是唯一专注编码智能体的 AI 工程师大会 AI Engineer CODE，地点在旧金山（San Francisco）；发布这次访谈，是为了让听众对过去一年编码领域的规模、野心与变化有心理准备，并预览明年。他问了杰伊 2027 年的 GitHub 会是什么样子，请听众听到最后。

  2. 2Universe 主题演讲刚结束：台上没讲完的，交给工作坊查看原文 →

    正式访谈在杰伊的主题演讲刚结束后录制。肖恩祝贺又一次成功的 GitHub Universe；杰伊说今天要讲的东西很多，而且都是好内容。肖恩指出，其实还有不少内容没来得及在台上讲完；杰伊连声同意。肖恩举例说，安全相关内容以及今明两天的各种工作坊，就是让人可以上手键盘亲自试；杰伊补充：为的就是看看这些东西到底怎么工作。这段短对话把后面的安全、产品和数字讨论都垫了起来。

  3. 3每秒一位新开发者：2.25 亿用户与 Octoverse 关键统计查看原文 →

    肖恩为播客听众重申头条数字：他专门查了一年有多少秒，因为杰伊说今年每一秒都有一位开发者加入，那就是约 3150 万。他先前提到的总数是 2.20 亿，杰伊立刻纠正为 2.25 亿，并打趣「谁还在来？」肖恩接话说：每一秒都有下一位。肖恩认为大家容易忽略这些图表的冲击力，因为人们默认 GitHub 就该一直能用。杰伊正式列出：平台上有 2.25 亿开发者，覆盖世界上每个国家；去年的 Octoverse 报告（口播作 Octiverse）里，每一秒都有一位新开发者加入，而且这已是连续第二年。报告中的其他主要统计包括：179 亿次代码推送（code push）、343 亿次提交（commit）、13 亿个拉取请求。开源社区继续建设与分享，比去年还多，增长了两倍半；平台上开源社区或项目的贡献约 21.5 亿次（字幕作「2 1.5 billion」，按口播更可能是 2.15 billion，中等把握）。

  4. 4GitHub 作为代码社交网络：智能体让更多人能一起构建查看原文 →

    肖恩对工程师听众强调，这些数字背后是数据库写入、文件写入和元数据处理；GitHub 是一个代码社交网络。他问曾在社交网络工作过的杰伊：经营这个网络是什么感觉。杰伊提到 Ning 和 Facebook 确实有某种模式，但终端用户群体不同。他认为，在当下 AI 的变化里，社区现在可以容纳多得多的人：过去 GitHub 的用户往往是软件工程师、产品经理或设计师；现在你不必先成为一名熟练的软件工程师才能用 GitHub，编码智能体可以代做很多事，你也可以把一个想法分享出去。他前几天和另一位记者聊天，对方在做实验后决定创建一个仓库、分享给别人并收集反馈。在他看来，这是世界用 AI 一起学习、一起构建的另一种方式。他在当天主题演讲里也说：这个社区最了不起的一点是，你不必独自构建，大家都在一起构建。

  5. 5智能体还需要拉取请求吗？可配置的平台原语查看原文 →

    肖恩提到一个重要背书来自彼得·施泰因贝格尔（Peter Steinberger）及其 OpenClaw：他大概属于把 GitHub 用到极限的前 0.001% 用户。彼得一个有意思的推动是「拉取请求是否该终结」，以及这会如何随智能体改变。杰伊说彼得团队很好合作，他们不断逼着 GitHub 变得更好，而这正是他们欢迎的——技术在快速进步，他们想持续迭代、持续构建。新范式和新工作方式出现时，平台会继续演化、适应和改变；如果某个概念不再有用，或不希望它成为强制要求，那它可以做成可配置的。但要记住，面对 2.25 亿开发者——大企业、小团队、学生等等——他们必须提供一个包含许多概念的平台，然后由你按自己的工作方式把这些概念组装起来。杰伊自己有些只是摆弄、试想法的仓库，并不走拉取请求：他不断往里砸想法、不停构建，不想处理议题（issue）或拉取请求。平台应该提供这些能力，他们会继续适应。

  6. 6仓库里什么算「代码」：Markdown 文件夹、Java 与 .NET查看原文 →

    肖恩提出，代码或许是比可执行软件更高一层的抽象。杰伊主题演讲里很突出地展示的一个仓库，来自肖恩的一位演讲嘉宾马特（Matt，字幕作 Matt PCO，姓氏不易从语音确认）：那只是一个 Markdown 文件夹。这让他想到 GitHub 上「这个仓库 76% 是 Rust」这类语言占比——50% 之类的数字现在好像没那么重要了。那么仓库是什么、代码是什么、他们在存储什么？因为你需要的远不只是可执行文件。杰伊同意这一点，但强调仍然存在大量代码：想想所有用 Java 和 .NET 写成、支撑当今关键业务的大型系统，它们仍在做安全修复、现代化、优化和修缺陷。内容类型跨越很广，有的已经有几十年历史，有的则是他们说话这会儿还在被推进生产环境（字幕作 viodated，按上下文或为 vibe-coded／deployed）。因此工具必须灵活，外面的选择也很多；他们相信开发者需要选择。杰伊自己作为开发者，会因为个性或手艺而对某些工具很挑剔，并用工具来表达这份手艺。

  7. 7Copilot 套件、Fusion 与模型路由查看原文 →

    肖恩认为 Fusion 是一件大事：在他看来，它像是对「套件／线束」（harness）的一层元抽象。Copilot 是第一个 harness，大概三四年前推出——杰伊说「四年左右」。harness 最根本的工作是把模型能力用到极致，其中很关键的一块是模型路由（model routing）。他问为什么 GitHub 要在这个领域建立领导力。杰伊说，他们当天发布了更多关于 Copilot harness 的信息，这套东西已经做了一段时间。其中软件开发工具包（SDK）部分很重要：你可以用这套 SDK 去构建其他应用，他自己和很多人都这么做过。harness 支持很多能力，但核心原则之一是多模型（multi-model），你也可以选择从何处接入这套套件。他们在持续改进它，并按形势调整：模型上下文协议（MCP）、编码或其他所需工具，以及不断进来的不同模型。有了 harness 之后，还需要一层智能：把一项任务、一段提示——亦即最终会变成一个完成的软件工作单元的东西——拆开，在某种程度上卸下工程师的认知负担，因为面前有这么多价格与性能各异的模型；然后告诉你：我们可以帮你优化，让你又快又便宜地得到最好的质量。他们还有很多想法，会继续迭代。杰伊的看法是，harness 与 Fusion 会一起起伏、配合解决问题：harness 负责编排你的工具与工作方式，Fusion 则帮你在今天如此多的选择里判断该用哪个模型。

  8. 8手机、桌面与 VS Code 同一会话，上下文在一处复利查看原文 →

    肖恩认同模型选择很重要，并提到他曾在这档节目里采访过萨蒂亚·纳德拉（Satya Nadella，口播作 Satia），这也是微软越来越强调的信息。他很喜欢他们做的「每个界面上都有 Copilot」：有很好的移动应用和桌面应用。他问：界面上是否需要创新，还是只要做微软品牌版本、把模型层做好就行？杰伊认为两者都要。这正是他当天讲的：每一层都在演化——底层的基础设施、存储、计算、网络与安全；平台层则包括 Git、GitHub Actions、AI 网关（AI gateway）以及支撑 Git 的许多其他服务；再往上是工作流和不同界面。把整条「铺好的路径」（paved path）都做好很重要，所以他们要在技术栈的每一层创新与演进。另一个要点是：当你使用 GitHub Copilot 应用、VS Code（Visual Studio Code）或 GitHub.com 时，它们现在都通过同一套 harness 相连。你可以在手机上发起一项工作，再到桌面或另一台笔记本上继续；或者有了新想法就丢进手机，让它继续跑。重要的是，上下文始终跟着你：仓库、议题、拉取请求、安全发现；你用哪个模型并不重要，记忆、偏好，以及他当天早上谈到的智能引擎，都在一处为你复利。今天如果在一家供应商的工具和另一家之间切换，它们的智能并不会叠加在一起。他们想解决的就是：借助平台和工具把工作做得更多、更便宜、更好、更快，同时你仍可高度定制——换模型、用 Fusion、用其他工具都可以。

  9. 9密钥在落地前被拦住：Code Review Max、高级安全与 npm查看原文 →

    肖恩把安全留到后面：GitHub 责任重大，最近的 PHP 相关事件也让安全成为焦点。他问杰伊希望大家知道 GitHub 在为人做什么。杰伊说工作很多，要做的也还很多。从产品或功能看，他们谈到 Code Review Max，应能帮助发现更高严重度、更隐蔽的代码缺陷；现在生成的代码多得多，质量标准不能下滑，代码审查和 Copilot 代码审查就是用来守住这条线的。其次是安全与 GitHub 高级安全（GitHub Advanced Security），现在加上了 AI 扫描技术。主题演讲演示里，达米安（Damian）不小心推送了一段密钥（secret），系统在它进入仓库之前就拦住了。他们还有更多深度扫描，不只看表层漏洞，后续还会有更多能力；当天有多场深入讲解和工作坊，可以把更复杂的 AI 扫描接入你交付软件的工作流。微软安全团队与 GitHub 安全团队也在大量协作：既加固平台，也与开源维护者合作，例如限制 npm 等包管理器当前的暴露面、设置时间延迟、下线已被入侵的仓库。这些是每天都在做的改进，和社区、开源项目、维护者一起推进；整个微软都在加大加固投入，这件事人人都放在心上。

  10. 10依赖该换成 20 个，还是把开源做安全？查看原文 →

    肖恩谈到安全与开源的关系：GitHub 和开源供应链的前提曾是「代码很贵」；现在代码也许变便宜了，安全审查也许也变便宜了，于是有一种意见认为，最安全的做法是把一切都内置（vendor）或重写，不再依赖开源。更具体的说法是：我的依赖大概有 2000 个大家都在用的核心软件，它们都是脆弱面，也许该减到 20 个。他问杰伊对此有没有看法，或者这是否太过冒险。杰伊说这个问题并不离谱，他们也常被问到人们在怎么做，但这不是万灵药：你有 2000 个开源项目，丢掉 1980 个、留下 20 个，那被丢掉的 1980 个就得自己维护。你必须选择把资金、人员和时间投向何处。开源里正在发生的许多事仍然重要而有价值，而且不会停止；如果有变化，开源对企业、构建者和创作者的价值只会从这里继续增加。他主张解决问题的方式是：把开源里的东西做安全，而不是人人都走进某种围墙花园（walled garden）。
