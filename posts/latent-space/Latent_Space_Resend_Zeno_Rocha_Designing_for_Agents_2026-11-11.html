一句话概述

Latent Space 主持 swyx（肖恩·王）在棚里与 Resend 联合创始人兼 CEO 泽诺·罗查（Zeno Rocha）对谈：从 Dracula 主题到「邮件界的 Stripe」，再到智能体如何挑选邮件 API、送达率、MCP 与为机器而写的文档。swyx 是该公司天使投资人。

核心要点

  • 截至录制当天早上，Resend 服务 430 万用户、逾 12 万付费客户，SDK 下载量已超过 SendGrid 两倍以上，年经常性收入约 1000 万美元。
  • Claude Code 推荐 Resend 的比例超过 60%；泽诺把「被人问起时必须是第一名」当成新一代分发，并为此改定价页 Markdown、补 FAQ 与 llm.txt。
  • 送达是一门排队与信誉的艺术：错开批次、管理 IP 池、默认信任再快速拦截；打开率因苹果预读而失真，点击追踪切勿共用易被连坐的域名。
  • MCP 用量大约每月翻倍，八月底约 120 万次调用，工具从不到 20 个增至 80 多个；第一个 MCP 由 a16z 的 Yoko 开源做出。
  • 他们正从 Amazon SES 下沉到自有「金属层」，并即将推出面向智能体的多收件箱 API；同时坚持手写各语言 SDK 与免费档。
  • 约 50 人远程团队刚开始企业销售；泽诺在女儿幼年时创业，如今在巴西等待二胎，并坦陈对家庭与公司的亏欠感。

  1. 1冷开场：从 Dracula 主题到「邮件界的 Stripe」查看原文 →

    泽诺·罗查（Zeno Rocha）在冷开场里报出一组数字：今年早些时候 Resend 的 SDK 下载量已经超过 SendGrid，现在更是其两倍以上；截至录制当天早上，Resend 为 430 万用户提供服务，付费客户刚过 12 万，客户里既有华纳兄弟（Warner Brothers）、HBO，也有大量独立开发者。他们还拦下过一个一次挂上约 2 万个不同顶级域、来自多家注册商的日本团伙；公司目前大约是 1000 万美元年经常性收入（ARR）。泽诺说，他宁愿活在这个现实里，也不愿做成 1 亿美元公司、却让女儿不愿意和他玩。主持人 swyx（肖恩·王）在棚里介绍嘉宾：两人认识于泽诺还是独立黑客、因 VS Code 主题 Dracula 而出名的日子——泽诺当年曾是 2020–2022 年间 GitHub 最活跃的开源贡献者之一，直到现在很多人仍先想到 Dracula 而不是 Resend。泽诺自称是前端 / HTML5 出身，并不懂邮件基础设施，只是用过 Mailgun、Mailchimp、SendGrid，觉得这个巨大市场里没人真正服务开发者，于是按「邮件界的 Stripe」来做。swyx 主动披露自己是天使投资人：泽诺那份备忘录非常直接——Mailchimp、Postmark 已退出，SendGrid 已被 Twilio 收走，谁来做这件事？华纳兄弟这个 logo，是他在有 AI 之前某个周六在数据库里按域名筛选、看到 WBG（Warner Bros. Discovery）才发现的。

  2. 2当智能体来替你选 API查看原文 →

    swyx 说自己投过三十多家公司，Resend 那次是他听过最直白的路演之一。更关键的是一次亲身经历：他已经在 Cloudflare 配好了域名、DNS 和 DKIM，只想「一个平台一把 API 钥匙」，可模型仍然坚持「你必须加上 Resend」。他调侃泽诺是不是买通了 OpenAI 或 Anthropic；泽诺说但愿真有人可买，但其实从第一天就把「被人问起邮件服务时必须是第一名」当成新一代分发战场——当年是 Heroku，后来是 Netlify、Vercel，这一代不会再走老渠道。swyx 补了一句现场观察：Claude Code 推荐 Resend 的比例超过 60%。两人随即转入正题：要把海量邮件真正送进收件箱，人们通常没想到哪些脏活。

  3. 3怎样把信送进收件箱查看原文 →

    泽诺强调，邮件不能像应用那样靠堆 GPU 或水平扩容解决：Gmail、Outlook、Yahoo 的规则各不相同，这是一个很「老派」、极度依赖关系和信誉的行业。他们早期极其外行，反而成了优势——传统服务商一上来就要填发送量表格、再等两天人工审核，多数情况下直接拒绝；Resend 选择把摩擦留给自己、默认让开发者先用起来。做了三四年之后，他才充分理解同行为什么要设那道门：欺诈、钓鱼和滥用无处不在，公司内部为此建了不少「不怎么对外讲」的系统。具体架构上，若把 10 万封邮件一次性砸向 Gmail，对方会限流并先观察打开、归档、删除等互动，再决定后面怎么处理。因此要把最活跃的收件人排在队列前面，并在不同服务商之间错开批次；还要购买、审查 IP 段历史，把发件人分到不同 IP 池并做长期均衡。新客户会被主动限速，因为邮箱服务商想看到「持续抬升」的发送曲线，而不是「一周爆发一次再长时间沉默」——后者正是滥用者的典型模式。那个日本团伙一次提交约 2 万个新域（许多域名刚买两天）、站点甚至不返回 200、或使用仿冒域名做外展，都是风险信号。产品侧则把最佳实践做进去：发送洞察、AI 链接/拼写检查，以及从 HTML 自动抽出 Markdown 生成纯文本版本——泽诺说这显著提升了送达率，因为垃圾邮件过滤器不必再解析复杂 HTML。

  4. 4打开率失真，以及「默认信任、快速拦截」查看原文 →

    纯文本没有嵌入图，也就没有传统打开率。打开追踪靠的是一枚 1×1 透明 GIF：一旦图片被加载就算「已打开」。但苹果近年的隐私与摘要功能会在邮件落地前预读内容，垃圾过滤器也会预先检查图片，打开率已远不如从前可靠，于是行业更依赖点击追踪。泽诺警告：点击链接和图片 URL 都应与发信域名一致。把追踪链接改写到服务商自己的域名，看起来方便，却会带来「吵闹邻居」问题——只要有一个滥用客户用该域发送钓鱼邮件，共享追踪域就可能被列入黑名单，解封要数天甚至数周，整家公司都会被拖下水。Resend 一开始也这么做过。哲学上，泽诺把传统准入比作「先坐 18 年牢再证明你是好公民」；他想要的是默认信任，一旦退信率、投诉率和邮箱服务商反馈出现异常，就迅速拦截并沟通。大多数情况其实是误用（「技能问题」）而不是蓄意滥用，不必为了坏人把整套产品变得更难用。

  5. 5客服迭代到「第四版」：只用文档链接回复工单查看原文 →

    swyx 提到 Resend 有一份让邮件更安全的公开承诺，并拿自己投过的 Railway（杰克）作比：同样极度开发者友好、也必须把支持做大。泽诺把客服比作已经迭代到「第四个大版本」：第一版只是「找个人坐在椅子上」；很快发现必须有人主动减少工单，于是第二版请来有领域知识的人，但仍不够超前。他们定过一条很硬的政策：回复工单只能附文档链接，不能直接给答案——先花大概一个半小时写知识库文章，然后再把同一条链接反复发出去，知识库因此快速长起来。去年 12 月他们大约有 100 万用户，现在约 400 万，继续堆人头解决不了问题。泽诺坚持保留免费档，因为他自己就是靠 Heroku 等免费产品起步的工程师。DNS 配置则是今天最大的支持摩擦源。

  6. 6「永远是 DNS」：Domain Connect 与行业关系查看原文 →

    泽诺承认，眼下大部分工单仍然是用户搞不定 DNS：CNAME、A 记录、TXT 往哪贴，经常贴错。Lovable、Bolt、v0 带进来的新用户更不会排障。swyx 说自己现在直接让 Codex 或 Claude Code 这类「电脑使用」智能体去改 DNS、跑 dig。Resend 则押注一条很少有人维护的协议 Domain Connect——相当于「域名界的 OAuth」：点几下授权、不用手打记录。Cloudflare 已支持，他们又说服 Vercel 加入；作为服务商，还要推动各 DNS 注册商落地。这个行业很怪：GoDaddy 对这项能力要价很高，联系 IONOS 相关的人花了好几个月。swyx 两周前第一次用，感觉就像用 Plaid 或 OAuth，只要你信任 Domain Connect，就没什么可填错的。泽诺坦言创业时并没有「Gmail 内部关系人」，后来才电话沟通、并招来从 Postmark 创立之初或 15 年前就在 Mailchimp 做送达的人，复用那张关系网。他庆幸选的是基础设施即服务，而不是普通软件即服务；至于 AI 后来会如何重塑这个行业，起步时完全没有预研。

  7. 7React Email 当引流，以及如何看待 SendGrid 与 Twilio查看原文 →

    开源的 React Email 被泽诺比作他们的「Next.js」：先免费修好写模板这一步，再自然引出「模板写完了，用 Resend 来发」。文档里甚至手把手写了如何对接 SendGrid、Mailchimp、Mailgun，他希望这是给整个生态的礼物。React Email 并非先做了再派生公司，而是做 Resend 时用户研究里反复听到的痛：设计师丢来 Figma，开发者还得切图、写邮件专用的表格 HTML 和内联 CSS，Outlook 还有特殊注释。React 在这里更像编译器：一次书写、适配各客户端；还可引入 Tailwind 设计令牌、用 TypeScript 做校验。邮箱里不能跑 JavaScript，所以没有状态、手风琴或动画，本质是 JSX 模板。泽诺还见过 Mailgun 创始人：对方说研发的 90% 都在跟滥用者打仗，所以很快把公司卖掉，并劝他别进这行。他最敬畏的对手始终是 SendGrid——「怎么可能打得过」——直到今年 SDK 下载量反超并超过两倍；不过按实际发信量，SendGrid 仍因大客户而领先。swyx 指出 Twilio 收购 SendGrid 是为了做成全渠道通信平台，估摸市值约 130–150 亿美元。泽诺很钦佩 Twilio 当年「去问你的开发者」的定位，但对创始人杰夫·劳森（Jeff Lawson）离开后（还买下了洋葱报）以及他们在邮件和短信上「睡大觉」感到可惜。谈到其他渠道：WhatsApp 对个人免费，但企业消息要走 Meta、将会收费；语音、私信、Slack 以及 Pylon 这类共享支持工具也都被点到，但泽诺真正在意的是「如何触达自己的受众」。

  8. 8先站在 SES 之上，再自己下沉到金属层查看原文 →

    swyx 回忆 freeCodeCamp、昆西·拉尔森（Quincy Larson）那份约 500 万订阅的通讯，走 Amazon SES，一个月大概 5000 美元，非常便宜。Resend 起步同样站在 SES 上，先把精力放在开发者体验：各种语言的 SDK、如何用 Lambda 发信的指南。隐患很快出现：事件要接 SNS，日志要 CloudWatch，量大了还要 SQS，再自己做 webhook，表面 5000 美元背后是一整套 AWS 装置。另一家 YC 公司 AgentMail 选择继续建在 SES 上、不跟亚马逊抢底层；Resend 却认为已经到了该「下沉到金属层」的时候，已经做了几个月，即将宣布。最难的是自己买整段 IP、管理 IP 池、按邮箱服务商做流量控制，并维护与服务商的关系；一旦这层基础设施到手，就能给用户远为细致的可观测性——信到底送到没有、落在哪个 IP、是不是进了促销标签——而不再是「发出去就只好信」。有意思的是，他们花大量时间把控制台做得很美，客户却说自己几乎从不打开。发送路径上，这家历来是 Node.js / TypeScript 店铺，最近已在发送链路上改用 Go，并开始尝试 Rust；泽诺调侃现在「语言不再重要」，换快的就行。

  9. 9MCP「回来了」：从 20 个工具到 80 多个查看原文 →

    几个月前不少人断言 MCP 已死、只剩 CLI。泽诺不太追风口，他要的是「无形」的产品：API 优先，覆盖不了的用例交给接口。MCP 用量大约每月翻倍；到八月底已约 120 万次调用（此前约 50% 的月增速，随后变成接近每月翻倍），人们越来越多从 Claude Desktop 或 Codex 开始工作。第一个 MCP 其实是投资方 a16z 的 Yoko 以开源、本地形式做出来的，后来应泽诺要求转到 Resend 名下；要做远程 MCP，他们不得不回头重做整套权限，并补上 OAuth，再配上 Datadog 可观测性、争取进各实验室的官方商店。swyx 站在买家角度说，官方维护非常重要：Plausible 的 MCP 是 Sentry 团队做的，即便他信任 Sentry，仍决定丢掉 Plausible、改用有官方 MCP 的 PostHog；作为消费者，他也会因为 Strava 有 MCP 能读跑步数据而用它，而 X 那种只能在桌面、不能在手机上用的本地 MCP 让人沮丧。工具是不是太多会把模型搞糊涂？他现在没那么担心：上线时大概不超过 20 个工具，现在已有 80 多个，还在补长尾，目标是 100% 覆盖控制台能力（用量计费、邀请成员、开通/删除账号），这比做到 90% 难得多。swyx 还批评 Next.js 与服务器组件让人轻易把数据绑在页面上、默认做不出公共 API；正确做法是无头后端，前端只是众多客户端之一。Resend 的 API 最初就开在 Next 上，账单高到受不了，才迁到传统 Node 服务器，现在用 monorepo 复用代码。Cloudflare 的 MCP 只有「搜索 + 执行」两个工具，Resend 是明显的反共识；泽诺前一天发给 swyx 的投资人更新，就是用自己的 MCP 拼起来的。

  10. 10手写 SDK、用命令行申请工作，以及给智能体的收件箱查看原文 →

    CLI 也在增长，只是不如 MCP 猛。泽诺某个周末做的招聘页提供三种投递方式：网页、命令行交互模式，以及内置 skill——可以直接让 Claude「申请 Resend 的产品设计师岗位」。他会特别看从来自 CLI 的申请，因为说明对方愿意多走一步。有人会说招聘该交给 Greenhouse 或 Ashby，不必在这种地方打磨；泽诺的哲学是：不为只服务旧金山、纽约、Wi-Fi 很好的 Mac 用户，而要照顾像他在巴西长大时那样、用糟糕 Windows 和烂网的人。这也是坚持免费档、并且坚持人工打磨每个语言 SDK（看过 Stainless、Fern 等生成器，但不满意）的原因——哪怕 400 万用户里用 .NET / Java / Rust 的只有约 500 人，这几百人也值得。产品上他们还做了多人实时邮件编辑器，公司全员大会就在私有 Resend 账号里、20 人一起改同一封信再群发；有的团队讨厌把模板塞进代码库，只想要可视化编辑器加模板 ID，有的则要源代码托管。访谈当天正赶上 Superhuman / Grammarly 的 Astra 发布，swyx 几乎没睡。话题转到「智能体读信」：swyx 大部分邮件交给 Poke 和 Superhuman，并提到估值约 25 亿美元、尚无收入的 Instinct。Resend 已有入站（inbound）邮件，下一步是用 API 批量创建几十个收件箱，并提供已读、标星、标签等接口，对标 Missive、Help Scout、Front，即将推出，还给了 swyx 功能开关。送达方面，泽诺印象里至少 60% 的量在 Gmail，随后是 Outlook、Yahoo，苹果也因隐私和「隐藏我的邮箱」而更严格，产品里甚至有向苹果登记的向导。信誉已从纯 IP 转向域名：交易邮件与营销邮件应分到不同子域，例如 updates / notifications；Resend 自己的投资人邮件走 confidential.resend.com。仿冒域名看起来就像钓鱼，所以「上 .com」仍然值得。
