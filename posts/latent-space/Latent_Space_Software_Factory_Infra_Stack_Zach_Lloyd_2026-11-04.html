  2. 2什么是软件工厂：可度量的云端智能体系统查看原文 →

    Zach 定义：软件工厂是云端、有角色分工与一定自主性的智能体系统，必须可度量、闭环，让团队能调优、基准测试并建立「规模化 AI 开发」信心。常见误区是把「大量用 agent 写代码」笼统叫工厂，或拼一堆自动化就指望变成「印钞机」。他主张工厂应在代码中明确定义，能在某时刻运行并测量表现；Warp Factories 平台要求按产品表面（product surface）各有一座工厂，把模糊自动化集合变成可编排、可观测的实体。

  3. 3用代码定义工厂：YAML、双角色与接入点查看原文 →

    工厂作用于一组仓库，绑定技能、MCP 与工作流（分诊、规格、实现等），工作流本身用代码定义——Warp 用 YAML 声明仓库、MCP 与集成。两种角色：产品工程师通过现有工具（Slack、Linear/Jira、GitHub、API/MCP）把工作项丢进工厂启动预定义流程；另一类是建设/运维工厂的人。关键是所有入口汇入同一系统，避免工具碎片化。

  4. 4集中化 traces：成本、吞吐与在线评分查看原文 →

    集中化后可看到团队在各产品工厂上的编码代理实时 traces（含 Slack 对话、computer-use 截图、编排步骤）。多数公司仍停留在工程师各自用 Claude Code/Codex 本地环境，缺少中心化。度量维度包括：DORA 类交付时长、每合并 PR 的人工干预次数与吞吐、按人/按 SDLC 阶段切片的成本。另有「评分器」（online evals）：啰嗦度、效率、代码质量，以及公司自定义失败模式（如破坏构建的改动）；以 LLM-as-judge 对历史会话回看打分（例：冗余测试膨胀代码库、浪费 token），并控制采样率以控评测成本。

  5. 5谁在用控制台：平台/DevX 与去「手感」评测查看原文 →

    swyx 追问展示的是不是 CTO 视角。Zach：主要用户是平台/DevX 与工程管理者，不是每位一线工程师的日常 IDE；目标是系统化榨取 Claude Code/Codex 等在组织内的价值。原则是存储、可观测、可度量，把「推特上哪个 harness/模型更好」从 vibe 拉回测量。还可为工厂配置触发式入队；自我改进环：代理盯评分失败（例：分诊步骤 54 个同类失败，因未 spawn 子代理调查），直接对工厂定义提 PR，未来还想对建议变更重放历史 runs 验证是否真改善。

  6. 6自有任务基准：模型×harness 矩阵与路由查看原文 →

    「基准测试」=把真实编码代理 runs 策展进套件（如前端任务），再对模型与 harness（Warp 自有、Claude Code、Codex、Pi 等）做矩阵重放，得到类似 SWE-bench/Terminal Bench、但基于本公司真实任务的成本–正确率图（目标左上：低成本高正确）。例：某任务集上 GPT-5.6 约 95% 正确、均价约 $6；GLM-5.3 Flash 约 93%、约 $2——可据此做模型/harness 路由。Zach 称之为「工厂工程」：用工程方法确认 coding agents 部署方式正确。

  7. 7工厂技术栈：声明式定义到编排与入口查看原文 →

    Zach 给出栈式视图（无论是否用 Warp）：底层用声明式代码定义工厂（类比 Terraform）——版本化 AI/产品开发生命周期、可分支测试、可回滚，且 coding agents 能直接改定义实现自改进；上一层汇集 agent 对话与产物，支持失败模式分析与变量重放；再接入 MCP，并按组织（市场/销售/工程）做权限隔离；独立可插拔计算层（Warp 主用 Namespace，也可 Daytona/Modal/E2B），Linux 沙箱外还需 Mac VM 跑 iOS 模拟器做 computer-use；推理与 harness 开放接入（烧现有 Anthropic/OpenAI/Google 承诺、自建推理、ACP 兼容 harness）；改进层之上是编排器（按定义推进阶段、选模型与技能、触发自动化）；入口哲学是嵌入现有知识工作工具——约 60% 工作从 Slack 起，也可任务跟踪器或终端 Claude Code 先写再交规格，整体 API/MCP 驱动、偏无头基础设施。

  8. 8从 $80/PR 到 $15–20：调优结果与适用规模查看原文 →

    Warp 内部起初约 $80/PR（分诊等步骤滥用高价 Opus、子代理过多）；用内置观测与基准调优后降到约 $15–20/PR，过去一月吞吐升约 40%，回滚率未升。适用对象：约 5–10 名工程师起才划算，越大实施越重；几人小团队别上，用 Claude Code/Codex 订阅更快。成长型创业（约 10–100 人）若在 Slack+Linear/Jira「快乐栈」上可较自助接入；多人频道可把崩溃/反馈流直接喂工厂并按代码域拉人。过小团队及极度定制基建的巨头（如自建平台的 Uber、Ramp 一类）不是好契合客户。

  9. 9订阅 vs API、商业定位与 AIE 演讲预告查看原文 →

    按 API 计费可比一堆订阅贵 5–50 倍；有小公司靠轮换多张约 $200 订阅硬撑——最便宜但不可扩展、损工厂收益，规模上来也不被允许。约 $200 套餐可换得约 $8000 级 API 额度，这使「纯 coding agent 转售」难赚钱（Cursor 做成后转模型实验室被 Zach 视为认清经济账）。Warp Factories 定位是编码代理优化与生产力平台，而非 token 转售。Zach 下一场演讲将谈工厂工程时代工程师的两种角色——产品工程 vs 工厂工程——以及如何工程化「建造软件的系统」。招聘与内容：warp.dev、工程/GTM/数据/设计岗位，以及 Twitter @Zach Lloyd。
