一句话概述

安德森·霍洛维茨节目对谈 First Person Labs 的肯。这是他首次公开谈论正在做的事：一个名为 Second 的「用户模型」或可携上下文。它在本地分析你电脑上已有的事件流——按键、应用切换、消息和各个渠道——再让 Grokbot、Codex 等其他智能体来询问它，而不必每次重新解释你的偏好。讨论重点包括安全架构、机密推理、成本，以及它怎样从「可携上下文」变成个人基础设施。产品已可在 two.computer 试用。

核心要点

  • Second 不是又一个 Grokbot 或 Dot，而是你唯一受信任的个人数据管家，其他智能体会与它对接；可以临时拉起子智能体，但一致性存储只有一个。
  • 电脑操作系统已经在提供近乎连续的事件流，问题是如何安全地分析它。肯说人们严重低估电脑已经知道多少。
  • 若你不信任他们，原则上可以自带 token，在笔记本电脑本地分析数据；他们也提供带可信执行的推理。机密推理靠英伟达等硬件证明「只有模型在跑、没人能看见」，这与「零数据保留」那种政策承诺不同。
  • 粗算下来，若用十个智能体、每秒 60 个 token、按 Opus 5.5 计价，可能一天约 1000 美元；若用 DeepSeek Flash，大约一天 60 美元。自公司创办以来，token 价格已下降一半以上。产品今天已可使用，但他们还在扩大推理产能，希望负责任地放开。
  • 肯的学术背景包括佩尔西·梁（Percy Liang），并与丹·博内（Dan Boneh）这类安全研究者有过合作。他们后来把界面收得很窄，目前主要是短信和应用程序接口，以便把系统理解和安全先做对。

值得看 / 可跳过

值得看。这不是空泛的「个人人工智能」愿景稿，而是第一次公开讲 Second 的产品形态、安全模型和真实成本，并有主持人作为早期用户的具体例子：活动气象更新、编码时截图说「修好」就够。自动字幕没有说话人标签，两位主持人全名也不完整，按对话轮次和台词启发式标注，中等把握。

适合人群

关心个人智能体、可携上下文、机密推理，或正在用 Grokbot、Codex 却厌倦每次重新解释自己偏好的人。

    开场就抛出核心判断：人们严重低估电脑已经知道多少。编码智能体不必再听你解释，截一张图说「修好」，它就该知道你要修什么。First Person Labs 想做的，是自动建立一个人的模型，并把控制权交还本人。肯首次公开谈论这件事。对重度使用 Grokbot 的主持人来说，它的位置是可携上下文：你对 Grokbot 说「去跟我那个东西谈谈，弄清我想要什么」，两边开始对话，你再说「给我买张机票」，它就该知道你说的是哪趟航班——座位偏好、想提前多久到机场、飞头等舱还是普通舱，今天这些还得对「爷爷」解释好多轮。OpenAI 前一天刚发布两款有网络能力的新模型，肯一段时间没用 Codex，但一直在用 Second，重新打开 Codex 时可以说「去问我的 Second 现在是什么情况」，过去的工作和额外上下文都还在。用户模型是一个过程：从基础的工件、生命中的人、偏好开始，再分析你说话、呈现自己和分享信息的方式，也许还会拿其中一部分去训练模型，慢慢从可携的 Codex 上下文，变成某种对你自己的表征。他爱用蝙蝠侠与阿尔弗雷德的比喻：阿尔弗雷德不必每次审核「这是不是蝙蝠侠」，因为他有一个足够好的你的模型。Second 会保持为「第二个」：不会变成第三、第四个，而是你唯一受信任的个人数据保险库；可以临时拉起随后消失的子智能体，但提供价值的是那份一致的存储。

  2. 2电脑其实已经知道很多：从原始事件流到主动找上你查看原文 →

    主持人作为极早的用户，惊讶的不只是它了解你是谁，而是它把各个渠道都接得很好，而这在系统上其实非常难，尤其要同时做到安全和私密。肯说，你的电脑上已经有近乎无限的事件流：切换了哪些应用、在哪些网站上停住、如何打字、无线网络如何连接，这些是苹果、微软甚至 Linux 的操作系统已经在给的。问题是能不能把它彻底分析掉，全天候叠上智能体。先合成「这段在某个应用里的打字可能是在发消息」，再看你在浏览器和 Codex 之间切换是在做研究还是写文档，再分层建立起理解，加上已有的连接器，就能较好把握你想做什么。一位主持人举了自己没主动要求的例子：它发现某段对话里情况变了，实时更新活动天气预报，告诉他们是否该准备帐篷。另一个主持人也会收到 Second 发来的短信，提醒他某段正在进行、自己却没想到的对话。肯把生产力分成几层：对一封新邮件做出反应很容易，甚至可能有九个个人智能体同时提醒你，让你拿到十条通知；更难的是「反思型」生产力——把数月前你说过的话、最近朝某个目标做的事、优先级、待办和偏好连起来。未来与电脑的互动，不该再是你必须先开口问；这些系统已经够聪明，不该还让人去问。

  3. 3不必只信他们的话：自带 token、机密推理，以及本地优先的存储查看原文 →

    一想到「这东西看得见你做的一切」，人们会立刻「哇」一声。肯认为你本来就不该立刻信任它。这是一种更被动、更环境式的人工智能，必须想清楚数据去哪、能对数据做哪种推理。若你不信任他们，原则上可以自带 token，在笔记本电脑本地给 Second 做分析。他们也提供带可信执行的推理供应商。多数人自带的其实是 OpenAI 或 Anthropic 的 token，所以他们想提供一个更稳的选项：用这些 token 时，没人在看数据，有时靠政策保证，有时靠硬件保证。这就是正在获得关注的「机密推理」：把模型放进开启机密计算开关的 GPU 里，可以证明里面只在跑模型、没人能看见，你信任的是英伟达这类硬件，而不必信任跑模型的那一方。这与「零数据保留」不同，后者本质是供应商的政策承诺，尽管也有法律约束。他们希望机密推理成为默认，尤其个人数据都该走这条路；这是技术上可证明的，要检查硬件和签名，第三方供应商也在跟进，他认为 OpenAI 上个月的公告里也开始提供这类选项。存储上也不是把数据上传到多租户大桶里和别人混在一起。一种是「Second 本地」：数据留在本地，只有你选择的供应商和推理才会出去，有点像偏执的人把密码库留在本地而不是丢进 Dropbox。云端备份也可以先走类似 iCloud 或密码管理器的架构：先在本地加密再上传，只在用户动作下、在可认证的机密容器里解密，从而把加密、云存储和机密推理的证明链走完。

  4. 4它怎么决定该不该说：以及一天可能要 1000 美元还是 60 美元查看原文 →

    主持人追问：若有人问你的 Second 要某人的日程，或开玩笑问「乔尔在瞒什么」，它怎么知道不该默认往外倒信息？大语言模型很难给出强保证。肯区分确定性保证和基于推理的保证：密码这类东西必须用确定性规则，永远不该进保留系统；推理类保证则取决于上下文有多丰富，再用它指导「哪些数据可以分享」。他不会让别人随意访问自己的 Second，但会在里面建立一个对马提尼的模型，理解他们惯常的互动——比如马提尼不会凌晨三点给他发消息，若真有凌晨三点的消息，更可能是垃圾或有人假冒。你没法为所有情况写完规则，确定性规则可以做后盾，但提示注入这类问题无法一劳永逸解决，只能随模型能力变强而变好。系统必须从一开始就可携，能在任何模型上跑，包括将来的本地推理。成本目前很重：粗算一个智能体全天候跑、每秒 60 个 token，若跑十个、按 Opus 5.5 计价，可能一天约 1000 美元；若用 DeepSeek Flash，大约一天 60 美元。这个成本会迅速下降，眼下还不是给所有人的，尤其适合忙碌的专业人士和经常在工具之间切换的人。自公司创办以来，token 价格已下降一半以上。原则上也可以做「更松的服务水准」：在「对你理解有多深」和「有多贵」之间权衡，也就是在测试时多推理，还是在缓存时就持续分析出更深洞察。产品今天已可使用，但他们还要再扩大推理产能和支持，确保数据被控制、安全，因为这是一种会碰到大量数据的新工具。

  5. 5最意外的用处：截图说「修好」，以及上下文在手机和电脑之间不断档查看原文 →

    作为用户，主持人发现它有用的方式超出预期。肯说，对开发而言，它是极好的记忆：你不必再向编码智能体解释任何事，截一张图说「修好」，它就知道你要修什么。他还经常在路上，于是需要「上下文连续性」：在笔记本上浏览，合上盖再拿出手机，同一份上下文仍知道你截至这一分钟在做什么，可以接着写那封邮件。系统里的上下文其实还远未被用满，还需要挖掘、应用搭建和交互设计才能释放潜力。不是所有任务都需要最贵的模型：判断「你在日历里移动了一个邀请」这类语义上有意义的时刻，不必上 Fable；「朱尔斯这周的目标是什么」才需要很贵的模型，而且不必频繁跑。Second 的核心是一套套件设计问题：什么时候用什么模型。新模型会不断出现，例如他们提到的 Jeff 就非常擅长检索：关于你的数据很多，测试时的查询又是动态的，它能立刻取回。因此它必须变成模型的混合，主要也是为了成本效率。今天的用法是安装应用、授予一些权限、指定 token，然后它开始在事件上流转。连接器能提高样本效率，让它学得更快，但原始电脑事件流同样重要。后台智能体几乎不需要你再做什么，并开始向外提供应用程序接口：十分钟前你做了什么、下周优先事项、提醒、生命中的人与流程。起初这更像可携上下文，智能体可以查询；往后会有越来越多接口，应用可以建在上面。一位设计师朋友对按钮和颜色的偏好被 Second 捕捉后，做自己的个人应用时迭代少了很多。肯把它比作当年的 Altair 8800：电脑刚出来时什么都做不了，要自己编程，几年后有人做出电子表格才真正有用。个人基础设施上也可能出现类似的「杀手级应用」。

  6. 6还不是贾维斯，但已经更接近；现在只留下短信和接口查看原文 →

    有主持人希望将来能在家里看到那种 1970 年代电影里、屏幕上可以对话的头像，嫌现在的 Second 虽然聪明，却没有形体。肯说，贾维斯被忽略的不只是智能，而是它无处不在：在门上、盔甲里、屏幕上，那种连续和普遍很难做到。更长远的设想是：每个人都有一个 Second，所有设备只是输入，再把同一份东西送到屏幕，甚至身边浮动的球体这类输出上。主持人提到伊恩·M·班克斯《文化》系列里那些漂在身边的具身人工智能。无处不在的计算谈了几十年还没到来，最接近的是苹果 iCloud 那样的笔记同步，但还没有「你的上下文和理解无处不在」的人工智能版本。若厨房里有一台 iPad，今天操作系统限制很多，可以把 Second 当作云端的 MCP：只要设备能上网、是智能体、能理解接口，它就可以在那里；以后会有装在各种界面上的应用，设备本身则很难做。眼下一个好用的办法是用 Grokbot 的语音模式，开车时让它去和你的 Second 对话。收尾问到肯的背景：导师是佩尔西·梁，也与丹·博内这类安全研究者有过合作，走的是非常硬核的系统与安全路线，但产品用起来却是愉快的用户体验。公司里其实有两类完全不同的问题：基础设施和交互。他们在交互上犯过很多错，后来决定把表面收窄，只留下短信和应用程序接口，让人们用对自己的理解去搭建，而不是他们自己把所有界面做完。理论上也可以把它当全功能的协作智能体在笔记本上跑 bash，但他们有意保持最小，好让交互更顺。肯请听众到短网址 two.computer 去试用，若认同这个使命也可以加入，要做的事还很多。

肯

人们严重低估了电脑已经知道多少。你不必再向编码智能体解释任何事，截一张图，说一声「修好」，它就该知道你要修什么。问题于是变成：能不能把这些信息彻底分析掉？Grokbot 缺少、而 First Person Labs 能补上的上下文是什么？眼下最大的问题之一，就是人们还得开口去问。这些东西已经非常聪明，你本不该还要去问。可如果你有一个会自己慢慢建立起来的用户模型，这些分析又一直在后台进行，你就可以立刻把这份上下文分享出去。

他们本质上是在创造一个「人的模型」，再把控制权交给这个人。一想到「这东西看得见你做的一切」，人们会立刻「哇」一声。若你不信任他们，原则上可以自带 token，在笔记本电脑本地分析数据。主持人感谢肯第一次公开谈论 First Person Labs 正在做的事。

马提尼

一位主持人说自己是重度 Grokbot 用户，问 First Person Labs 会嵌在他现有用法的哪个位置。肯说，用法是把一份上下文带到 Grokbot 那里，也就是可携上下文。你对 Grokbot 说：去跟我那个东西谈谈，弄清我想要什么。然后两边开始对话，你再发「给我买张机票」这类提示，它就该知道你说的是哪趟航班。

肯

若问 Grokbot 缺少什么、First Person Labs 能补上什么，肯反而想问相反的问题：First Person Labs 还有什么是没有的？你在给自己建一个用户模型：飞机上的座位偏好、希望提前多久到机场、飞头等舱还是普通舱。今天这些还得向「爷爷」解释，往往要多轮提问。可如果有一个会自己建立起来的用户模型或模型视图，这些分析又一直在后台做，你就可以立刻分享出去。例如 OpenAI 前一天刚发布两款有网络能力的新模型，他一段时间没用 Codex，但一直在用 Second，于是可以重新打开 Codex，让它去问自己的 Second 现在是什么情况，过去的工作和额外上下文都还在。

Second 将来会不会变成「第一」，还是会始终通过其他智能体来走？肯认为用户模型是一个过程，得从某处开始：先是基础的工件、你做过的事、生命中的人，也许还有偏好；再慢慢分析你说话、呈现自己和分享信息的方式，并在上面堆出更多工件和理解，其中一部分也许会用来训练模型。时间久了，它会从可携的 Codex 上下文，变成某种对你自己的表征。他爱用的例子是蝙蝠侠和阿尔弗雷德：若蝙蝠侠想买一个芝士汉堡，让阿尔弗雷德去办，阿尔弗雷德不会先审核「这是不是蝙蝠侠」，他会直接去买，因为作为管家——或者说智能体——他已经有一个足够好的你的模型，你信任他能把事办成。

肯认为，现在同时拥有很多个人智能体，大概只是过渡。智能体也会像人一样开始分工：有的专注购物、浏览亚马逊，因为它们有数据和连接；有的专门保护你的数据、与你的利益对齐。Second 想成为的，就是你应当能信任、把人生上下文放进去的那个保险库，并随着时间引导你与软件世界甚至硬件世界对接。它会保持为「第二个」，不会变成第三、第四个：你那个真正了解你、并与所有其他智能体互动的、唯一受信任的个人数据智能体。可以临时拉起随后消失的子智能体，但提供价值的，是那份一致的存储。

乔尔

主持人总结：First Person Labs 做出一个叫 Second 的东西，它有你的上下文，其他智能体再来和这个「第二个你」说话。但这还没说出另一件他们做得很辛苦的事：它还能拿到一个人的数字上下文，比如消息、聊天，某种程度上也包括电子邮件。作为最早的用户之一，真正打动他的，不只是它知道他是谁，而是它把各个渠道接得非常好——而这恰好是非常难的系统问题。

肯

肯承认这确实很难，尤其要做到安全、私密。大致的工作方式是：你的电脑上已经有近乎无限的事件流。你使用电脑时，切换了哪些应用、在哪些网站上停住、如何打字、无线网络如何连接，这些是苹果、微软甚至 Linux 的操作系统已经在给的。问题是：能不能把它彻底分析掉？在这股原始流上全天候叠上智能体。于是可以先合成：这段在某个应用里的打字，可能意味着你在发消息；你在浏览器和 Codex 之间切换，可能是在做研究，或在写一份谷歌文档。再分层建立起理解，加上已有的连接器，就能较好把握你想做什么。人们严重低估电脑已经知道多少，它们就在那里，等着被用上。

马提尼

另一位早期用户说，最近它已经变得不可或缺：它会发消息告诉他，你和某人的这段对话还在进行，而且情况好像变了。他们前一天在规划活动，当时有百分之二十的气象概率，它会实时更新预报，告诉他们是否该准备帐篷。他并没有要求它这么做。另一位主持人也有同样体验：会收到 Second 发来的短信，内容恰恰是他需要知道、却没想到的某段正在进行的对话。那些自己会忘掉的事，它真的在替他抓住。

肯

这又回到「人的模型」：理解此刻什么可能对他重要。人们谈生产力，常常是在需要的时点提醒你，但生产力有很多层。第一层是反应型：一封邮件进来了，网上还有一个梗，于是你因为另外九个个人智能体也在提醒你，而收到十条关于这封邮件的通知。反应型生产力直截了当、容易做。更难的是他称为反思型的那些：把许多事件、很长的时间跨度连起来——数月前你说过这句话，最近你又在朝这个目标推进，这是你的优先级，待办里还有这些，而且你更偏好这种方式。把点连起来，才能给你好得多的生产力。这也许提示了未来个人与电脑互动的方向：不再聚焦于对事情做出反应，而是思考能给用户哪些干预，有哪些事甚至可以在不问的情况下替用户撤销。他认为这是眼下最大的问题之一：人们还得去问。这些东西是超级智能，你本不该还要去问。

乔尔

主持人想对听众说得很具体：它创建一个叫 Second 的东西，以非常安全的方式访问你的数字上下文，包括按键、消息、各个渠道和数据，并由此成为某种个人管家，就像阿尔弗雷德，再去和其他智能体互动。它本身不是一个智能体，不是 User Instinct、Grokbot 或 Dot，而是把上下文提供给那些智能体。他自己用很多个 Grokbot：一个管合成器，一个管房地产，一个甚至帮他处理家庭事务；但他只有一个 Second，它们都会和这个 Second 对接。那将来会不会有第三、第四、第五个，还是永远只有这一个管家？

不必只信他们的话：自带 token、机密推理，以及本地优先的存储

↑ 返回总结
乔尔

一位主持人仍是偏执的安全人士，比他的同伴乔尔更快采用这些东西——乔尔连社交媒体都很晚才上。他喜欢 Second，肯的背景、动机，以及他们关于安全架构的长讨论，让他安心下来。可当人们想到「这东西看得见你做的一切」，第一反应往往是「哇」，不会立刻信任。他请肯谈谈架构，以及驱使他这样构建的原因。

肯

肯觉得，这在某种程度上是一种会与以往很不同的新形态人工智能。以前是你发起一次互动，再拿回一些结果；这次更被动，也更环境式，它会一直在。因此必须想清楚怎么对人讲、怎么做架构、数据去哪。说到人工智能，归根到底只有两件事：数据和推理。你有这些数据，就要定义能对它们做哪种推理，这也做进了 Second。首先，推理可以由你选择。若你不信任他们，原则上可以自带 token，用这些 token 驱动 Second，在笔记本电脑本地分析数据。他们也提供带可信执行的推理供应商。长期看，多数人不会自带 token，因为他们带来的往往是 OpenAI 或 Anthropic 的 token。他们想提供一个更稳的选项：用这些 token 时，没人在看数据，有时靠政策保证，有时靠硬件保证。这就是正在获得关注的「机密推理」：把模型放进 GPU 里，打开名为机密计算的开关，就可以证明里面只在跑模型、没人能看见。你不必信任跑模型的那一方，你信任的是硬件，也就是英伟达。

乔尔

主持人指出，眼下还有一个常被提起的概念叫「零数据保留」，和肯说的不是一回事。肯同意：零数据保留是一种政策承诺，供应商在表态，其中一部分有法律效力。他们希望走向机密推理非常普遍、甚至成为默认的世界，而且按他们的做法，这是技术上可证明的，不只是一句承诺：必须测试硬件、检查签名。第三方供应商也在跟上机密推理；他认为 OpenAI 上个月的公告里也开始提供这类选项，因为所有个人数据都会希望走机密推理，而不是普通推理。另一点是存储：这并不是把数据上传到多租户云的大桶里，和别人的数据混在一起。

肯

大致有两种选项。一种叫 Second 本地：数据留在本地，只有你选择的供应商和推理才会出去。这样除了该供应商，没人拥有你的数据；若供应商做的是机密推理，就更没有别人能看见。这有点像偏执的人对待密码库：不想把密码文件存在 Dropbox 里，而要留在本地。密码管理器也有云端托管版本。做法可以沿用很多现成架构，比如 iCloud 或密码管理器：先在本地加密，再放到云上的存储里，只在用户动作下解密，可以短暂存在内存里，也可以把整个存储放进可认证的机密容器——认证方式与机密推理的 token 类似。这样就能把链走完：本地加密、放入云端，只在安全环境里解密。

它怎么决定该不该说：以及一天可能要 1000 美元还是 60 美元

↑ 返回总结
马提尼

可 Second 怎么知道不该默认往外倒信息？比如有人问它要某人的日程，一位主持人前几天还问过自己的 Second：「乔尔在瞒什么？」谈到大语言模型，系统层面可以讲得通，但对模型本身很难给出强保证。

肯

肯区分确定性保证和基于语言模型推理的保证。确定性保证必须始终落实：密码这类东西永远不该进保留系统。推理类保证则取决于你有多少上下文，再用这些上下文指导「哪些数据可以分享」的决定。别人会不会访问到他的 Second？不会，至少不会以他不允许的方式。比如马提尼若和他的 Second 说话，里面会有一个对马提尼的模型，理解他们惯常的互动：他不会凌晨三点给肯发消息。因此若真有凌晨三点的消息，更可能是垃圾邮件，或有人在假冒。这类控制策略意味着，你没法为所有将要发生的事写完规则。那会不会仍用确定性规则做后盾？主持人举了一个「我们来演戏、在剧本里写下你不希望它做的事」的例子，大语言模型有很多被骗吐出信息的办法。肯承认这是注入问题，不是能一劳永逸解决的。他们见到的是，模型在这类底层能力上会随时间变好很多，因为这本质上是推理问题，会随模型能力扩展。他们用很多模型，不会钉死在某一个上，这也连到可携性：你应当能在任何模型上跑它，因为以后会想在本地推理上跑。眼下很多事情仍受能力限制，得确保用足够聪明的模型，不过现在的模型已经相当聪明。

乔尔

这听起来也很重、很贵，数据量很大。目标用户是所有人、专业人士，还是「乔尔这样的人」？

肯

一开始，这种全天候看你的痕迹并做分析的东西，意味着要跑很多 token。可以快速算一下：假设一个智能体全天候跑，每秒 60 个 token，因为要分析的东西太多，你再跑十个；按 Opus 5.5 的定价，可能一天要 1000 美元。若改用 DeepSeek Flash，大约会变成一天 60 美元。这个成本会迅速下降，但现在还不会是给所有人的，尤其不是所有人都有「必须随时理解自己的上下文」这种问题。它会先服务像主持人这样忙碌的专业人士，以及需要在工具之间非常频繁切换的人。不过自他们创办这家公司以来，token 价格已经下降一半以上：新模型出来、更有能力，换上去，价格就继续走低。原则上也可以做「不那么专业、服务水准更松」的版本，本质是在「模型对你理解有多深」和「有多贵」之间权衡，也就是在测试时多推，还是在缓存时就持续分析、得到关于这个人更深的新洞察。缓存时分析很花钱；若只留下今天的原始日志，到测试时再根据原始日志回答，通常会慢得多，或许要十倍时间，因为模型得当场推理。产品今天已经可用，但他们还要再扩大推理产能和支持，希望以非常负责任的方式放开，确保人们的数据被控制、安全，因为这是一种会碰到大量数据的新工具。

最意外的用处：截图说「修好」，以及上下文在手机和电脑之间不断档

↑ 返回总结
乔尔

作为用户，主持人发现它有用的方式超出预期。肯大概是最顶级的重度用户，因为他就是创建它的人。他们请他谈谈更令人惊讶、也更有用的使用场景。

肯

对开发而言，它是极好的记忆，能记住他们想做什么。你不必再向编码智能体解释任何事，截一张图说「修好」，它就知道你要修什么。他也经常在路上，于是有一种他称为「上下文连续性」的东西：你在笔记本上浏览，合上盖，再拿出手机，同一份上下文仍知道你截至这一分钟的状态，你可以在那里继续做事，一起写那封邮件。他觉得现在仍相当早，对使用场景的理解还不够；系统拥有的上下文其实远未被用满，还需要很多挖掘、应用搭建和交互设计，才能释放潜力。上下文越多，模型往往工作得越好。

马提尼

主持人说，自己在世界级前沿模型和更「商品化」的模型之间，没看到太大差别，很好奇他们为 Second 做这些事时有没有同样感受。

肯

肯觉得这是好问题。若问的是：你电脑上刚刚发生了一个语义上有意义的时刻，比如你打开日历、移动了一个邀请，那并不需要 Fable，这类任务有很多。你想理解的信息是分层的。另一种信息是：朱尔斯这周的目标是什么？那才需要很贵的模型，但你不必非常频繁地跑它。所以 Second 本质上是一套套件设计问题：什么时候用什么模型。正因为此，系统从一开始就必须可携。总会有更多模型出来。比如 Jeff，结果非常擅长检索：关于你的数据很多，测试时的查询又是动态的，它能立刻取回。因此它必须随时间变成模型的混合，主要也是为了成本效率。

今天的用法是：安装一个应用，它会要一些权限，你授予权限，再指定自己的 token，然后它就开始在事件上运转。连接器有帮助，这是一个样本效率问题，能让它学得更快；原始的电脑事件流同样重要。后台智能体几乎不需要你再做什么，它们会一直跑，并开始向外提供应用程序接口：有接口说明你十分钟前刚做了什么，有接口说明下周该做什么、你的优先级是什么，有提醒的接口，也有关于你生命中的人和流程的每周接口。起初这更像可携上下文，你可以把它带到任何地方，智能体可以查询；往后会有越来越多接口被加上，应用可以建在这些接口之上。是 Second 来做应用，还是人来做？他希望人发挥自己的创造力，也可以让 Grokbot 去建，告诉它去做。一个例子是：一位设计师朋友上了这个系统，他对按钮和颜色的特定偏好被 Second 捕捉到，于是在做自己的个人应用时，迭代少了很多。这让他想起几十年前第一台个人电脑 Altair 8800：它什么都做不了，要你自己编程，几乎没人做；几年后有人做出电子表格，它才变得特别有用。人们会想在「我有这么多关于自己的上下文」之上随便搭建，也许有人会撞上杀手级应用。这就是个人基础设施。

还不是贾维斯，但已经更接近；现在只留下短信和接口

↑ 返回总结
乔尔

界面会不会进化？他一直把 Second 看成一个你可以与之交谈的智能体，用户界面好像是别人的问题，但他们是否也打算在这上面创新？一位主持人直接提了个需求：希望回到家里，看到那种 1970 年代电影里、屏幕上可以对话的头像。Second 已经非常聪明，问它问题也很好，但它没有形体，这让他很受不了。若将来阿尔弗雷德能真的成为一个阿尔弗雷德，他会非常高兴。

肯

电影里常有贾维斯，我们一直在和贾维斯说话，可为什么还没有贾维斯？人们忽略了贾维斯的许多面向：不只是它聪明、能做事，更在于它无处不在——在你的门上、盔甲里、屏幕上。那种连续和普遍很难做到。更长远的未来，他想象每个人都会有一个 Second，所有设备都只是输入，再把同一份东西送到你看着的屏幕，甚至身边浮动的球体这类输出上。

马提尼

有主持人说，自己的科幻未来想象，基本上是从开始用 Second 时开始的：终于有一个东西感觉拥有上下文、了解他，对话是相关的，这让人觉得离那个未来近了一步。可我们仍被拴在这些设备上，若它能稍微从手机和电脑上脱离开，会更好。他也提到伊恩·M·班克斯的《文化》系列，认为那是最好的科幻之一，里面有最好的具身人工智能，会漂在你身边。无处不在的计算已经谈了几十年，却还没到来；最接近的是苹果 iCloud，笔记会同步，但还没有「你的上下文和理解无处不在」的人工智能版本。若厨房里有一台 iPad，想让 Second 在那里，现在该怎么做？

肯

眼下能做的还不多，因为操作系统把很多东西锁住了。今天可以把它当作云端的 MCP：无论你在 iPad 上装了什么，只要它有网络、是一个智能体、能理解应用程序接口，它就可以在那里。以后会有安装在各种界面上的应用，再往后也许会出现新设备，但设备很难做。眼下一个好用的办法，是让 Grokbot 打过来、开免提，用语音模式和它说话。Grokbot 的语音模式其实相当好，可以一边开车一边用。一种有趣的互动是：你解锁、打给 Grokbot，让它去和你的 Second 谈谈，一起把事情过一遍——这正是有的主持人已经在做的。眼下他们会先把精力放在让语音和聊天更自然上。

乔尔

最后还有一个问题。肯是非常硬核的系统人，导师是佩尔西·梁，也与丹·博内这类安全研究者有过合作，走来这条路的是非常硬核的安全工作，因此他在做一个既安全又好用的严肃系统。可当主持人和它互动时，又是一种愉快的用户体验。公司里会不会有点「人格分裂」：一边要建造诺克斯堡那样的基础设施，一边又要很好用？还是说大语言模型基本上已经把界面问题解决了？

肯

他们面对的是两类问题：基础设施问题和交互问题，而且犯过很多错，因为这是完全不同的技术栈。他们曾一度全力投入交互，结果发现其实很难，要把体验做得很愉快，里面有大量细节。他们意识到，让每个人拿着这份对自己的理解去搭建，会需要很长时间才能做对，所以他们希望赋能人们自己去做，而不是自己把所有表面都做完。于是他们决定把表面收窄：只留下短信，只留下应用程序接口，没有别的。理论上也可以把它当全功能的协作智能体在笔记本上用，它能跑 bash，但他们有意保持最小，好让交互更顺。主持人对肯的到来和产品发布表示祝贺。肯给听众留下的话是：今天就可以去试，短网址是 two.computer，他们希望尽快让大家用上；若你认同这个使命，也欢迎加入，要做的事还很多。
